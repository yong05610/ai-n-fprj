# 변경관리내역서 검토 — 학습경로 설정 (PM)

작성: PM, 2026-11-09(2차 검토 반영). 대상: 사용자가 작성한 `변경관리내역서.pdf`(인수 테스트 보완 사항, 학습경로 설정 부분). 각 항목을 현재 코드와 대조했다(`frontend/components/LearningPathWizard.tsx`, `frontend/lib/planText.ts`, `backend/schemas.py`, `backend/prompts.py`). **CR 번호는 사용자가 진행 순서를 정한 뒤 등록한다.**

규모: S = 문구·배치·간단한 계산(반나절), M = AI 프롬프트나 응답 항목 변경(1~2일, 실제 AI 호출 확인 비용 있음), L = 새 흐름·새 API(3일 이상).

| 1 | 학습목표: 직무 예시 버튼을 [목표추천]으로, 누르면 추천값 + 오른쪽 [AI 학습설계 미리보기]에 인사이트 | 버튼 `✦ 이 분야의 대표 직무·목표 예시 보기` → 누른 뒤 `✦ 예시 다시 보기`. 응답은 **직무 이름 3~5개뿐**(`RoleIdeasResponse.suggested_roles`). 오른쪽 미리보기는 계획을 만들기 전까지 안내문만 있음 | **타당.** 오른쪽이 처음에 비어 있고, 목표를 고르는 순간에 판단 근거가 없다 | ① 버튼 이름 `목표 추천`, 기존 문장은 버튼 옆 설명으로 ② 오른쪽에 직무별 한 줄 설명(무슨 일, 주로 배우는 과정) 표시. ②는 AI 응답 항목을 늘리는 **계약(DTO) 변경**이고, 보여 줄 내용은 사용자 결정 | ① S ② M |

## 2. 공통 선행 조건
- **목업 먼저:** 학습 경로 설정 화면을 바꾸는 항목(1, 1-2, 2, 3-2, 3 1단계)은 PM 이 `mockup/index.html` 의 `page-path` 를 먼저 고치고, 개발 지시서에 목업과 나란히 비교한 표를 요구한다(5C 에서 목업과 어긋났던 교훈).
- **테스트 기간 중 배포:** 테스터가 쓰는 화면이 바뀐다. S 묶음은 혼란을 줄이는 쪽이라 테스트 중에 반영해도 되지만, 설문 응답에 "어느 화면 기준인지"가 섞이므로 반영 날짜를 기록한다.

## 3. 내역서 양식
- **표지:** "태광엠앤에스 ERP 시스템 구축사업"과 다른 회사 로고가 그대로 있다. PaceMate 로 바꿔야 한다. 이 상태로는 저장소에 올리지 않는다(HWP·PDF 모두 커밋하지 않음).
- `유형`·`대책유형` 칸이 비어 있다. 제안: 유형 = 오류 / 개선 / 신규, 대책유형 = 즉시 수정 / CR 등록 / 연구 / 보류.
- 3번 줄에 "예를 들어"와 "시"처럼 한 문장이 표 줄바꿈으로 나뉜 곳이 있다.

## 5. 1차 검토에서 고친 것
- 조언 길이를 "200자 안팎"이라고 썼으나 실제 제한은 제목 200자, 내용 4,000자다.
- 3번 "가능할까"에 대한 안내가 이미 일부 있음을 확인해(가용 시간 비율, 초과 시 확정 차단) 1단계를 M 에서 S 로 낮췄다.
- 1②가 응답 항목 변경(계약 변경)임을, 4가 인사이트의 "평가 어조 금지" 규칙과 맞춰야 함을 추가했다.
