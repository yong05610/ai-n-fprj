## 발견 사항 (수정 요청 없음)
1. **목록에 없는 흔한 암호는 통과한다.** 예: `Dragon12#` 는 등록됐다(`dragon` 은 널리 알려진 흔한 단어). 흔한 암호 거부는 목록 4,000개와 패턴으로 하므로 모든 추측형 암호를 막지는 못한다. 사용자가 정한 8자 규칙의 한계로 기록한다(등록 카드의 확인 문구가 보완).
2. **로컬에서는 `X-Forwarded-For` 헤더로 IP 를 바꿀 수 있었다.** 원인은 이 서비스 코드가 아니라 uvicorn 기본 설정이 같은 PC(127.0.0.1)에서 온 요청의 이 헤더를 믿기 때문이다(`forwarded_allow_ips` 기본값). 배포 시작 명령(`uvicorn main:app --host 0.0.0.0 --port $PORT`)에서는 Render 프록시가 연결하므로 이 동작이 일어나지 않고, 코드는 `RENDER` 가 있을 때 가장 오른쪽 값을 쓴다. 그 값이 실제 사용자 IP 인지는 **배포 후 확인**한다(아래).
3. **전체 일시 중지를 일부러 일으킬 수 있다.** 서로 다른 IP 7곳에서 5번씩 틀리면 15분 동안 모든 사용자의 암호 로그인이 멈춘다(설계대로, 추측 공격을 막는 대가). 익명 사용과 이미 로그인한 사용자는 영향이 없다. 테스트 규모에서는 수용한다.
4. 흔한 암호 목록의 출처(SecLists, MIT): 공개 유출 암호에서 모은 목록이지만 개인 식별 정보는 없고, 이런 목록으로 흔한 암호를 막는 것은 널리 권장되는 방어 방식이다. **사용 가능으로 판단**한다.
5. `delete-data` 응답에 삭제 목록 필드는 원래 없다. DTO 를 바꾸지 않는 개발팀 판단을 수용한다.

## 미검증 (배포 후 PM 확인)
- firebase 모드에서 다른 브라우저로 로그인해도 **같은 UID** 가 되는지: 개발팀 보고(시험용 사용자 1명)만 있고 PM 은 직접 하지 않았다. 배포 후 배포 주소에서 확인한다.
- Render 무료 서버의 해시·로그인 시간, `X-Forwarded-For` 가장 오른쪽 값이 실제 사용자 IP 인지(다른 두 네트워크에서 틀려 보고 서로 차단되지 않는지로 확인).
- Firestore 보안 규칙(`credentials` 거부) 콘솔 배포(사용자 작업), 실제 휴대폰 화면.
- 화면 모양을 PM 이 브라우저로 직접 보지 않았다(개발팀 비교표만). 배포 후 사용자 화면 확인과 함께 본다.
