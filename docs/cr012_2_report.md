## 3. 변경 내용
**No.1① 목표 추천 버튼** — `✦ 목표 추천`(다시 눌러도 같은 이름), 아래 작은 설명. 불러오는 중 글자는 `예시 찾는 중…` → `추천 찾는 중…`(버튼 이름이 바뀌어서 맞춤).

**No.2 과정 추천 버튼** — `✦ 과정 추천받기` / `✦ 과정 다시 추천받기`.

**No.3 수준 콤보박스** (`LevelCombo`)
- 현재, 목표 각각 한 칸. 칸을 누르거나 오른쪽 `▾` 버튼 또는 아래 화살표 키로 목록이 펼쳐지고, 고르면 이름이 칸에 들어가며 같은 칸에서 바로 고칠 수 있다.
- **칸에 쓴 글자로 목록을 거르지 않는다**(브라우저 `datalist`를 쓰지 않고 직접 구현). 시험과 실제 브라우저에서 "전혀 다른 글자를 써 놓고 열어도 4개 모두 보임"을 확인했다.
- 순서(`current_level_order`/`target_level_order`)는 **마지막으로 목록에서 고른 항목**의 순서다. 이름을 고쳐 써도 안 바뀐다. 순서 번호는 화면 어디에도 없다.
- 목록에서 한 번도 고르지 않아 순서가 없으면 `목록에서 수준을 골라 주세요.`를 보이고 계획 만들기 버튼을 막는다. 이름이 비면(공백만도) `수준 이름을 입력해 주세요.` + 버튼 막힘. 이름 100자, 설명 2000자(입력칸에 같은 글자 수 제한도 걸었다).
- 목표 목록에는 현재보다 높은 수준만 보인다. 현재를 바꿔서 목표가 같거나 낮아지면 다음 수준으로 바꾼다(지금 규칙 그대로). 현재가 맨 위 수준이라 더 높은 수준이 없으면 목표 칸은 비활성이고 계획 만들기가 막힌다.
- 설명: 칸 아래 `설명 보기·고치기`(접힘). 목록에서 고르면 그 수준의 설명으로 바뀐다(지금과 같은 동작).
- 키보드·접근성: 위·아래(목록 안에서만 이동), Enter(고르기), Esc(닫기, 모달 같은 바깥 동작으로 번지지 않게 막음), `role="combobox"`, `aria-expanded/controls/activedescendant/haspopup`, `role="listbox"`/`option`/`aria-selected`, 문제 문구는 `aria-describedby`와 `role="alert"`.

**No.5 미리보기 과제 목록** — 과제마다 제목 줄에 연한 배경(`--lav`)과 둥근 번호 배지(1, 2, 3…, 전체 과제 순서). 과제 사이는 더 진한 테두리와 12px 간격. `과업 삭제`는 작은 글자 링크 버튼(`link-btn task-remove`, 10px, 회색 글자, 오른쪽 정렬). 입력 칸과 동작은 그대로(삭제 후 번호는 다시 매겨짐).

## 6. 미확인 / 참고
- 실제 휴대폰, 화면 읽기 프로그램(스크린리더)으로 읽는 소리, 배포(Vercel) 화면은 미확인. `aria` 속성은 시험과 소스로만 확인했다.
- 확인용으로 AI 호출 3개(목표 추천, 과정 추천, 계획 생성)는 브라우저에서 가짜 응답으로 바꿨다. 실제 AI 와의 연결은 1차(CR-012) 보고서의 실제 호출로 확인한 범위다.
- 작은 동작 보강 1건(지시서에 없던 것): 목표가 한 번 비었다가(맨 위 수준 선택) 현재를 다시 낮추면 목표를 다음 수준으로 자동으로 채운다. 이전 코드는 이때 목표를 비워 둔 채 두었다. 규칙("같거나 낮아지면 다음 수준")의 연장이다.
- `link-btn`을 쓴 `과업 삭제`는 글자가 작아 터치 영역이 좁다. 필요하면 PM 이 확대 여부를 정해 주세요.
- 확인용으로 `frontend`에서 `npm run build`를 실행했다. 이미 떠 있던 포트 3000 개발 서버(내가 띄운 것이 아님)와 `.next` 폴더를 공유하므로 화면이 이상하면 그 서버를 다시 시작하면 된다.
- 작업 폴더의 이 작업과 무관한 파일은 커밋하지 않았다: `docs/프롬프트와 응답사례연구.md`, `frontend/AGENTS.md`, `변경관리내역서.hwp/.pdf`.
