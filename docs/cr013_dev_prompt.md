## 1. 학습 삭제 버튼 (학습 과제 계획 화면, `WeeklyPlanScreen.tsx`)
배경: 학습 계획을 지우는 API(`DELETE /api/goals/{goal_id}`)는 있는데 화면에 버튼이 없다. 동시 진행 학습은 최대 2개라, 연습으로 2개를 만들면 새 계획을 만들 수 없고 지울 방법도 없다(전체 데이터 삭제뿐).

- 위치: 화면 머리 오른쪽(지금 "계획 저장됨 ✓" 자리), 아래 2번의 저장 상태 글자 옆에 `이 학습 삭제`(`btn danger small`).
- 누르면 확인 창(기존 모달 스타일, 목업 `delete-goal-modal`):
  - 제목 `이 학습을 삭제할까요?`
  - 본문 `{과정명} 학습과 그 과제 N개, 실행 기록 N건, 회고, 학습 인사이트가 모두 지워지고 되돌릴 수 없어요. 켜 둔 타이머도 멈춰요.` N 은 화면이 이미 불러온 값으로 채운다(과제 수 = 과제 목록 길이, 기록 수 = 과제별 기록 수의 합). 알 수 없으면 숫자 없이 같은 문장.
  - 둘째 줄 `AI 튜터 대화는 학습과 따로 저장되어 지워지지 않아요.`
  - 버튼 `취소`(기본 초점) / `삭제`(`btn danger`). Esc·바깥 클릭은 취소.
- `삭제` → `DELETE /api/goals/{id}`. 진행 중엔 버튼 비활성 `삭제하는 중…`. 성공하면 창을 닫고, 학습 목록·현재 학습을 다시 불러온다. 서버가 현재 학습을 남은 학습으로 바꿔 주므로(`_fall_back_active_goal`) 그 학습의 계획을 보여 주고, 남은 학습이 없으면 지금의 "학습 없음" 화면(경로 만들기 안내)을 보여 준다. 실패하면 창 안에 오류 문구와 다시 시도, 아무것도 지워지지 않은 것으로 다룬다.
- 다른 화면(대시보드, 실행 기록, 분석)으로 갔을 때 지운 학습이 남아 보이지 않아야 한다(각 화면이 들어올 때 다시 불러오는지 확인하고, 아니면 보고서에 적는다).

## 2. 저장 상태 표시 정리 (같은 화면)
배경: 지금 "계획 저장됨 ✓" 은 버튼 모양인데 대부분 눌리지 않고, 실제로 저장하는 것은 **추천 요일 변경뿐**이라 "계획 전체를 저장하는 버튼"으로 오해된다.

- 평소: 버튼 대신 **작은 상태 글자** `✓ 변경 내용 자동 저장됨`(목업 `.save-status`, `aria-live="polite"`).
- 저장 중: `저장 중…` 글자.
- 실패했을 때만: 오류 글자 + `다시 시도` 버튼(지금의 재시도 동작 `saverRef.current.retry()` 그대로).
- 저장 로직(`LatestWinsSaver`)은 바꾸지 않는다.

## 3. 대시보드 "종합 학습 현황" 행 강조와 이동 (`Dashboard.tsx`, `app/page.tsx`)
사용자 요청: 마우스를 올리면 색이 바뀌고 테두리가 생기며 살짝 움직이고, 누르면 실행 관리(학습 실행 기록)로 이동.

- 각 학습 행(`goal-row`)을 누를 수 있게: 마우스를 올리거나 키보드 초점이 오면 **연한 배경, 테두리, 위로 2px 이동, 옅은 그림자**(목업 `.goal-row.clickable` 값 그대로, 새 색 하드코딩 없이 기존 변수 또는 목업 값). 커서는 손 모양.
- **움직임 줄이기 설정**(`prefers-reduced-motion: reduce`)이면 이동·전환 효과 없이 색·테두리만.
- 누르면: 그 학습을 **현재 학습으로 바꾼 뒤**(지금의 학습 전환과 같은 API: `PATCH /api/user/profile` `{active_goal_id}`) **학습 실행 기록 화면**으로 이동. 이미 현재 학습이면 바로 이동. 전환이 실패하면 이동하지 않고 행 아래에 오류 문구.
- 접근성: 행 전체를 하나의 버튼으로(키보드 Tab 으로 가고 Enter·Space 로 실행), 화면 읽기 라벨 `{과정명} 학습 실행 기록으로 이동`. 행 안의 진행률 막대·숫자는 그대로.
- 휴대폰(마우스 없음): 누르면 바로 이동(강조 효과는 누르는 순간에만).
- 오른쪽 위 `종합 분석 →` 링크는 그대로.

## 5. 시험
- 기존 시험은 기대값을 고치지 않고 통과(기준: pytest 1370, npm test 219).
- 새 시험(소스·순수 함수 방식 가능):
  1. 삭제 확인 문구가 과제 수·기록 수를 화면 데이터로 채우고, 모를 때 숫자 없는 문장.
  2. 삭제 성공 뒤 다시 불러오기, 남은 학습 없음 → 학습 없음 화면, 실패 → 오류와 다시 시도, 진행 중 비활성.
  3. 저장 상태: 평소 글자(버튼 아님), 실패 때만 `다시 시도` 버튼.
  4. 대시보드 행: 버튼 역할·라벨, 누르면 현재 학습이 아니면 전환 후 이동, 현재 학습이면 바로 이동, 전환 실패 시 이동 안 함.
  5. CSS 에 `prefers-reduced-motion` 처리가 있다.
- 브라우저 확인(dev 모드): 넓은 화면과 360px. 삭제 흐름(학습 2개 → 1개 삭제 → 남은 학습 표시 → 마지막 삭제 → 학습 없음 화면), 대시보드 행 강조와 이동, 저장 상태 3가지.
