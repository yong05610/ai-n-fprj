# CR-013 수정 1 보고서 — 삭제 요청이 404 면 이미 지워진 것으로 처리

작성: 개발팀, 2026-11-09. 요청: `docs/cr013_verification.md` 의 "수정 요청 (CR-013 수정 1)". 프론트엔드의 삭제 흐름 한 곳만 바꿨다(백엔드·API 변경 없음).

## 1. 무엇을 고쳤나
- 문제: 첫 삭제 요청은 서버에서 성공했는데 응답만 끊긴 경우(느린 망, Render 재시작 중), `다시 시도` → 서버가 404 → 화면이 "삭제하지 못했어요"를 보이고 목록도 다시 불러오지 않았다.
- 수정: `runGoalDelete`(`frontend/lib/goalDelete.ts`)가 `DELETE /api/goals/{id}` 의 **404(`ApiError.status === 404`)를 "이미 지워짐"으로 보고 성공과 같이 처리**한다. 창을 닫고 학습 목록·현재 학습을 다시 불러온다(그러면 화면이 실제 상태를 보인다). 403·409·500·연결 오류 등 다른 오류는 지금처럼 실패(창 안 오류 + `다시 시도`, 다시 불러오지 않음).
- 화면 코드(`WeeklyPlanScreen.tsx`)는 그대로다. 이미 `runGoalDelete` 를 쓰고 `ApiError` 가 `status` 를 가지고 있어 그대로 동작한다.

## 3. 시험
**npm test 236건 통과(이전 235 + 새 1), pytest 1370건 통과(백엔드 변경 없음), `npm run typecheck`, `npm run build` 통과.** 기존 시험의 기대값은 바꾸지 않았다.

새 시험: 404 → `{ ok: true }`, 호출 순서 `delete → reload`. 같은 시험 안에서 403·409·500·0(연결 오류)은 계속 실패(`{ ok: false }`)이고 그때는 다시 불러오지 않음, `isAlreadyDeleted` 가 일반 오류·null 에는 false.

## 4. 실제 브라우저 확인 (dev 모드, Chrome 헤드리스, 7개 항목 통과)
학습 2개 → 계획 화면에서 `이 학습 삭제` 창을 연 뒤, **창 뒤에서 서버로 같은 학습을 먼저 지워** "응답을 못 받은" 상황을 만들고 `삭제`를 눌렀다.
- 서버가 실제로 404 를 줌 → 창이 닫히고 오류 문구 없음 → 목록을 다시 불러와 남은 학습(파이썬)의 계획이 보이고 지운 학습(영어)은 화면 어디에도 없음.
- 마지막 학습에서 서버 응답을 403 으로 바꾸면 창 안에 오류 + `다시 시도`가 보이고 학습 2개 중 1개가 그대로 남아 있음(실패 유지).
- 페이지 오류 0건.

## 5. 미확인
- 실제로 응답이 끊기는 네트워크(Render 재시작 중 등)는 재현하지 않았다. "서버에서 먼저 지워 404 를 받게 하는 방식"으로 같은 결과 경로를 확인했다.
- 확인용으로 `frontend`에서 `npm run build`를 실행했다. 이미 떠 있던 포트 3000 개발 서버와 `.next` 폴더를 공유하므로 화면이 이상하면 그 서버를 다시 시작하면 된다.
- 작업 폴더의 이 작업과 무관한 파일은 커밋하지 않았다: `docs/프롬프트와 응답사례연구.md`, `frontend/AGENTS.md`, `변경관리내역서.hwp/.pdf`.
