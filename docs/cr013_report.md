## 3. 삭제 뒤 각 화면이 최신 상태인가
화면은 `current` 값에 따라 하나만 그려지고(들어올 때마다 새로 마운트) 각 화면이 마운트될 때 서버에서 다시 불러온다. 실제 브라우저로 확인했다.
| 화면 | 결과 |
|---|---|
| 학습 과제 계획 | 삭제 성공 → 학습 목록과 현재 학습(`/api/user/profile`)을 다시 읽음(`useGoalSwitch.reload`). 서버가 현재 학습을 남은 학습으로 바꿔 주어 그 학습의 계획이 보임. 남은 학습이 없으면 `진행 중인 학습이 없어요` 화면 |
| 대시보드 | 남은 학습만 표시. 마지막 삭제 뒤에는 행 없음 |
| 학습 실행 기록 | 지운 학습 이름이 화면에 없음 |
| 종합 학습 분석 | 지운 학습 이름이 화면에 없음 |

2. 삭제 흐름: 성공 뒤 다시 불러오기(삭제 → 불러오기 순서), 실패 → 오류와 불러오기 없음, 불러오기 실패가 성공한 삭제를 오류로 만들지 않음, 진행 중 비활성과 `삭제하는 중…`, 실패 뒤 `다시 시도`, 남은 학습 없음 → `none` 화면, 하나 남음 → 그 학습, 화면 소스(DELETE 호출, `reload()`, 창 2곳).
3. 저장 상태: 평소 글자(`✓ 변경 내용 자동 저장됨`), `저장 중…`, 실패에만 `다시 시도`, 옛 `계획 저장됨 ✓` 없음, 상태 글자가 삭제 버튼 앞, 저장 로직(`LatestWinsSaver`)이 그대로 있음.
4. 대시보드 행: 라벨, 역할·`tabIndex`·Enter/Space(소스), 다른 학습이면 전환 후 이동, 현재 학습이면 전환 없이 이동, 전환 실패 시 이동 안 함, 현재 학습을 못 읽으면 전환을 시도.
5. CSS: 강조 값, `:hover`/`:focus-visible`/`:active`, `prefers-reduced-motion` 안에서 이동·전환만 끄고 색·테두리는 유지, 터치용 `@media (hover: hover)`.

## 5. 브라우저 확인 (Chrome 헤드리스, dev 모드 서버, 40개 항목 모두 통과)
- **대시보드:** 학습 2개 행이 `role=button`/`tabindex=0`/라벨. 손 모양 커서. 마우스를 올리면 배경 `rgb(243,245,255)`, 테두리 `rgb(201,209,255)`, 그림자, `translateY(-2px)`로 바뀜. 움직임 줄이기 설정에서는 색·테두리만 바뀌고 이동 없음, 전환 시간 0s. 키보드 초점에도 같은 강조. Enter → 다른 학습이라 `PATCH {active_goal_id}` 1번 후 실행 기록 화면, Space → 현재 학습이라 PATCH 없이 바로 이동. 전환 요청을 500으로 바꾸면 이동하지 않고 행 아래에 오류가 보임.
- **저장 상태 3가지:** 평소 작은 글자(`SPAN`, `aria-live="polite"`, 버튼 없음), 요일을 바꾸면 `저장 중…`, 저장 요청을 실패시키면 빨간 글자와 `다시 시도` 버튼, 누르면 성공하고 글자가 돌아옴.
- **삭제 흐름:** 학습 2개(영어는 기록 1건) → 영어 삭제 창의 본문이 `영어 회화 기초 학습과 그 과제 3개, 실행 기록 1건, …`, 처음 초점이 `취소`, Esc와 바깥 클릭으로 닫힘(삭제 안 됨). 삭제 요청을 500으로 바꾸면 창 안에 오류 + `다시 시도`, 학습은 2개 그대로. 느리게 하면 `삭제하는 중…` 비활성. 성공하면 창이 닫히고 남은 학습(파이썬)의 계획 표시, 서버에 학습 1개이고 현재 학습이 그것. 다른 화면에 지운 학습 흔적 없음. 마지막 학습 삭제 → `진행 중인 학습이 없어요` 화면 + `학습 경로 설정으로 이동`, 서버에 학습 0개, 현재 학습 null.
