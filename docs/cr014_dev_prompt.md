# CR-014 개발 지시서: 학습 실행 화면의 주간 목표 계산과 과제 표시

작성: PM, 2026-11-10. 대상: 개발팀. 이 작업만 한다(다른 개선 후보 E-4~E-7 금지). 근거: `docs/execution_improvement_candidates.md` "E-1 확인 결과".

## 1. 해야 할 일 (사용자 승인 2026-11-10)
### E-1 주간 목표 달성 분모 수정 (결함)
- `frontend/components/ExecutionScreen.tsx:324` 의 분모를 **활성 학습의 `weekly_hours × 60`** 으로 바꾼다(대시보드 `weekly_target_minutes` 와 같은 값, 목업 `주 목표 420분`). `weekly_hours` 는 `GET /api/goals`(`GoalResponse`)에 있다. 프론트 `GoalOption` 타입에 없으면 추가한다(계약 변경이 아니라 기존 필드 사용).
- `주 목표 N분` 문구와 `주간 목표 달성 %`, `N분 / M분` 모두 이 값을 쓴다. 100% 상한은 유지한다.
- 기간이 `전체 기간`일 때: 분자가 이번 주가 아니므로 %를 계산하지 않는다. 카드에 `이번 주 보기에서 확인` 같은 짧은 안내를 표시한다(문구는 개발팀 판단, 보고서에 적는다).
- 활성 학습이 없거나 `weekly_hours` 를 못 읽은 경우 0 나누기·NaN 이 나오지 않게 한다.

### E-2 과제 설명 표시
- 과제 묶음 제목 아래에 `description` 을 12px 보조 글자로 표시한다(목업 `task-desc`: `<p class="small muted task-desc">`). 길면 2줄에서 줄임 처리 후 눌러서 펼치기는 하지 않아도 된다(줄임만). 설명이 빈 문자열이면 줄을 만들지 않는다. API 변경 없음.

### E-3 "이번 주" 보기에서 이번 주 과제만 표시
- 기간 선택이 `이번 주` 일 때 과제 묶음은 **이번 주에 배치된 과제 + 이번 주에 기록이 있는 과제**만 보인다. `전체 기간` 이면 지금처럼 전체.
- "이번 주 배치"는 과제가 여러 주에 걸칠 수 있어 `plan_week_start` 만으로 판단할 수 없다. 대시보드가 쓰는 `schedule.tasks_in_week`(`backend/schedule.py:134`, `main.py:1642`)와 **같은 규칙**을 써야 한다. 구현 방법은 개발팀이 정하되 **서버에서 계산해 응답으로 받는 방식**을 권장한다(예: `GET /api/tasks` 에 이번 주 여부 필드 또는 쿼리 추가). 프론트에서 타임라인 계산을 복제하지 않는다.
- 응답 필드를 추가하면 CLAUDE.md "계약 변경" 규칙대로 `backend/schemas.py`, `docs/erd_current.md`(해당 시), `docs/phase1_design.md`, 프론트 타입을 함께 갱신하고 보고서에 알린다. 기존 클라이언트가 깨지지 않게 선택 필드로 추가한다.
- 이번 주 날짜는 `backend/clock.py` 만 쓴다(Asia/Seoul, 월~일). `date.today()` 금지.
- 이번 주에 보일 과제가 0개면 빈 상태 안내(`이번 주에 배치된 과제가 없어요. 전체 기간에서 확인하세요`)를 표시한다.
