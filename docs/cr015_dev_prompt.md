# CR-015 개발 지시서: 글자 크기 상향(동적 글만)

작성: PM, 2026-11-10. 대상: 개발팀. 이 작업만 한다. 근거·분류·시험 결과: `docs/cr015_font_size_design.md` §0, §7. 사용자 승인: 2026-11-10(목업 확인 후).

## 1. 요구 (내역서 #9)
"시스템 전반에 아주 작은 폰트가 많아 읽기 불편함. 매번 쓰는 사람에게 의미 없는 **고정 안내 주석은 그대로**, **실행·사건마다 달라지는 글은 조금씩 키운다.**"

## 2. 해야 할 일
`frontend/app/globals.css` 의 `font-size`(px)를 등급별로 바꾼다. 표준 목업 `mockup/index.html` 의 `<style>` 이 이미 같은 규칙으로 바뀌어 있으니 **그 CSS 를 기준**으로 삼는다(`git diff 5614780 -- mockup/index.html` 로 확인).

| 등급 | 처리 |
|---|---|
| ⓐ 동적·조작 글 | 8→10, 9→11, 10→12, 11→12 (12px 이상은 변경 없음) |
| ⓑ 고정 안내 주석 | 변경 없음 |

**ⓑ(그대로)**: `.brand em`, `.nav-title`, `.kicker`, `.eyebrow`, `.card-head p`, `.small`, `.scope-note`, `.soon-note`, `.coach p`, `.modal p`, `.level-desc summary`, `.goal-switch small`, `.scope-label`, `.block-small`(안내성이면).
**ⓐ(키움)**: 위를 뺀 나머지 전부(통계, 과제·기록 제목과 메타, 날짜·시각, 버튼, 탭, 칩, `.pill`, 입력·라벨, 표, 튜터 말풍선·입력창, 타이머, 저장 상태, 막대 라벨, 인사이트 본문 등).
- 위 표에 없는 선택자는 **원칙(매번 같은 안내 문구 = ⓑ, 데이터·상태·조작 = ⓐ)**으로 개발팀이 분류하고, **분류 결과를 보고서에 표로** 적는다(PM 이 확인).
- `.small` 은 안내와 상태 문구("아직 기록이 없습니다")에 함께 쓰인다. 일단 ⓑ(그대로)로 두되, 상태 문구를 ⓐ 로 올려야 보기 좋은 곳이 있으면 별도 클래스로 분리해도 된다(바꿨다면 보고서에 목록).
- `.goal-switch label` 에 `white-space: nowrap` 추가("현재 학/습"으로 쪼개짐 방지, 목업과 같음).
- 구현 방식은 자유(값 직접 수정 또는 CSS 변수). 한 번에 다시 조정하기 쉬우면 좋다. 인라인 `style` 의 작은 글자(`fontSize`)가 TSX 에 있으면 같은 등급 규칙으로 처리한다.

## 3. 화면 확인 [필수]
폭 **1440, 900, 390** 에서 다음 화면을 연다: 대시보드, 학습 경로, 과제 계획, 실행 기록, 종합 분석, AI 튜터, 참고자료(있다면), 설정, 첫 화면·동의 모달, 관리자 화면 5개(관리자 계정 가능할 때).
- 확인 기준: ① 가로 스크롤 없음 ② 글자 잘림·겹침 없음 ③ 짧은 라벨이 쪼개지지 않음(`현재 학습`, 메뉴 항목, 탭, 칩, 버튼, 통계 카드 라벨) ④ 고정 폭 요소(`.searchbar` 220px, `.weekday-select` 92px, 모바일 하단 메뉴 `min-width: 66px`)에서 문제 없음 ⑤ 긴 문장이 한 줄에서 두 줄로 느는 것은 허용.
- PM 시험(목업 기준): 새 넘침 0건, 줄바꿈 증가 24곳(대부분 390px). **구현에서 이보다 크게 달라지면 보고한다.**
- 문제가 나오면 해당 곳만 더 작은 값 또는 `nowrap`/폭 조정으로 고치고, 무엇을 왜 고쳤는지 보고서에 적는다. 목업과 달라진 곳은 PM 에게 판단을 요청한다(스스로 목업과 다르게 두지 않는다).
