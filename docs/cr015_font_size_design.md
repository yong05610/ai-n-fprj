# CR-015 설계: 너무 작은 글자 키우기 (전체 시스템)

작성: PM, 2026-11-10. 상태: **설계(사용자 결정 대기)**. 요청: 사용자(변경관리내역서 #9, 2026-11-10 구두 설명: "너무 작은 폰트를 조금 키워서 문제가 없는지 판단하고 고친다"). **PDF 원문 확인(2026-11-10, poppler 설치 후 4쪽을 이미지로 직접 읽음)** — 아래 §0.

## 0. 내역서 #9 원문 (기능: 시스템 전반)
- **내용**: "시스템 전반에 걸쳐 아주 작은 폰트들이 많이 있어 읽기가 불편함."
- **분석/검토**: "매번 사용하는 사람에게는 의미없는(새로 사용하는 사람들이 들어와서 작동법을 이해하는데 필요한 주석 등) 것이 아니고, **실행할 때마다 달라지거나 사건별로 각기 다른 문자의 폰트는 조금씩 키워야 할 필요가 있음.**"
- 대응방안·비고는 비어 있음. 그 아래 "학습실행기록" 행 2개는 "준비중"(별개 항목).
- **해석(이 설계의 기준)**: 모든 글자를 일괄로 키우라는 뜻이 아니다. ① **고정 안내 주석**(처음 쓰는 사람을 위한 작동 설명, 항상 같은 문구)은 작아도 된다. ② **실행 때마다·사건마다 달라지는 글**(사용자 데이터, 기록·과제 내용, 상태, 결과, 오류·알림, 시각·숫자)은 **조금씩** 키운다. "조금씩"이므로 큰 폭 변경은 아니다. 아래 §2 안 A 를 이 기준으로 고쳐 쓴다(두 등급).

## 1. 조사 결과 (`frontend/app/globals.css`, 2026-11-10, 코드 읽기만)
`font-size` 선언 122개의 분포(px): **8px 15개, 9px 26개, 10px 34개, 11px 18개**, 12px 10개, 13px 이상 19개. 즉 **93개(76%)가 11px 이하**다.

| 크기 | 쓰이는 곳(예) | 판단 |
|---|---|---|
| 8px (15) | 날짜 `.day`, 기록 부제 `.record-select small`, 기록 삭제 버튼, 타이머 라벨·상태, 인사이트 안내, 대화 시각, 말풍선 시간, `.wbs-date`, 미니 막대 | **너무 작음.** 눌러야 하는 삭제 버튼과 타이머 상태까지 8px |
| 9px (26) | 통계 보조 줄, 진행 막대 라벨, 과제 부제, 태그 칩, 참고자료 링크, 표 머리글, 타이머 버튼, 요일 선택 | 너무 작음 |
| 10px (34) | **본문 기본**: 카드 설명, 버튼, `.small`, 입력 라벨, 튜터 말풍선, 입력창, 표 본문, 인사이트 본문 | 작음(본문이 10px) |
| 11px (18) | 버튼 `.btn`, 에러, 모달 목록, 콤보 항목 | 경계선 |

일반 기준(참고): 화면 보조 글자 12px 이상, 본문 14px 안팎이 읽기 쉽다. 이 서비스는 본문이 10px 이라 사용자가 "작다"고 느끼는 것이 타당하다. 최근 CR-013 이 조언 본문만 12px 로 올렸다(지금 가장 큰 본문).

## 3. "문제가 없는지" 확인 항목 (개발 지시서에 넣을 검증 기준)
1. **고정 폭 요소**: `.searchbar` 220px, `.weekday-select` 92px, 칩, `.task-no`, `.btn.small`, 사이드바(`nav-item`, 모바일 `min-width: 66px`), 통계 카드 4칸, 타이머 패널. 글자가 커져 잘리거나 겹치지 않는가.
2. **화면 폭 3종**: 데스크톱(1440), 태블릿(~900), 휴대폰(390)에서 대시보드·계획·실행·튜터·설정·관리자·동의 모달·첫 화면.
3. **한 줄 요소**: 통계 카드 큰 숫자 옆 `<small>`, 진행 막대 라벨, 표 머리글, 탭, 모드 띠(`.mode-banner`).
4. **누를 수 있는 것**: 8~9px 삭제·선택 버튼은 글자만이 아니라 터치 영역(최소 약 32px 높이)도 점검.
5. **글자 대비**: 연한 회색(#9aa0b0, #a0a6b4, #a8aebd 등 8~9px 글자) 색은 크기를 키워도 대비가 낮다. 이번에는 **색도 한 단계 진하게**(예: `--muted` 계열)할지 사용자 판단.
6. 테스트(`npm test`, typecheck, build)는 글자 크기와 무관하게 통과해야 한다. 크기 자체는 화면 확인이 필요하므로 **브라우저 확인은 사용자 몫**(PM 은 CSS 비교와 넘침 위험 코드 읽기로 검증하고 "화면 미확인"으로 적는다).
