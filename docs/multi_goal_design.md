# 복수 학습(목표) 운용 설계 결정

작성: PM(검증팀 겸임), 2026-10-22. 근거: 사용자 지시(대원칙 3건). 상태: **확정(2026-10-22, 사용자 승인: PM 제안안 전체 채택)**. 단 종합 분석(D)은 사용자 수정: 완료된 학습을 제외하고 현재 진행 중인 학습의 일정, 일자별 투입 시간, 진행률만 보여 준다. mockup 반영 완료(PM), ERD 반영 완료. 확정되면 mockup, erd_current.md, phase1_design.md, PRD, TASK.md 에 반영한다(코드는 개발팀 지시서로).

## 1. 사용자 결정 (원문 요지)

1. 학습 일정이 겹치는 계획은 2개 이상 만들 수 없다. 단, 진행 중인 학습의 일정을 나중에 바꿔서 생기는 겹침은 제약하지 않는다.
2. 학습계획과 학습실행기록은 한 번에 하나의 학습에 집중하고, 작고 간편한 전환 도구로 다른 학습으로 넘어간다. 대시보드, AI 튜터, 참고자료보관함은 모든 진행 중 학습을 대상으로 보여 준다.
3. 대시보드는 학습을 하나만 하는 사람이 많다고 보고, "최근 학습"(마지막 등록 또는 최근 접속) 영역과 "종합 학습 정보" 영역으로 나눈다.
4. 종합 학습 진행 분석 메뉴(학습 활동, 종합 진도)를 추가한다.
5. AI 튜터는 질문을 걸러서 답한다. 학습 일반(학습 방법, 요령)과 계획된 학습 주제 안의 질문에만 답하고, 그 외는 "학습과 관련 없는 질문에는 답변하지 않습니다" 안내 후 거부한다(토큰 절약).

## 2. 기존 결정과의 관계 (CLAUDE.md "핵심 결정")

- 바뀌는 것: 없음. 목표 개수 무제한(phase4_plan.md)에 "일정 겹침 금지" 규칙이 추가된다.
- 유지: UID는 토큰에서만, 계획은 확정 시에만 저장, 추천 요일은 마감일이 아님, 날짜는 Asia/Seoul(clock.py, week.ts).
- 튜터 거부 규칙은 "AI 결과는 서버가 규칙으로 검증하고 어기면 거부한다" 원칙과 같은 방향이다(Phase 6 범위).

## 3. 해결해야 할 모호한 점 (사용자 결정 필요)

A. **"일정"의 정의.** goals 에는 시작일이 없고 target_date(목표 완료일)만 있다. 안: 일정 구간 = [plan_week_start 또는 확정일, target_date]. 두 활성 목표의 구간이 하루라도 겹치면 새 확정을 거부(409, 코드 예 GOAL_PERIOD_OVERLAP). 이를 위해 goals 에 `start_date` 필드가 필요할 수 있다.
B. **어느 학습과 겹치는가.** 안: status=active 인 목표만 비교(completed, archived 는 제외).
C. **기존 학습의 일정 변경**은 겹침 검사를 하지 않는다(사용자 결정). 일정 변경 화면과 API 가 현재 없으므로 Phase 범위를 정해야 한다.
D. **종합 분석 메뉴의 MVP 포함 여부.** 14일 MVP 일정상 부담이 크다. 안: MVP 는 기존 데이터(완료 과제 수, 학습 시간, 목표별 진행률)만 쓰는 읽기 전용 집계 1화면으로 제한하고 히트맵 등 PRD 제외 항목은 넣지 않는다. 제외 항목은 post_mvp_backlog.md 에 둔다.
E. **튜터의 "학습 관련" 판정 방법.** 안: 서버가 먼저 분류(저비용 모델 또는 규칙)한 뒤 관련 질문만 본 호출로 보낸다. 분류 호출도 토큰이므로, 분류와 답변을 한 번의 호출에서 구조화 출력(관련 여부 + 답)으로 처리하는 안을 권한다. 오판 시(관련 있는데 거부) 사용자가 다시 묻는 경로가 필요하다. Phase 6 지시서에서 확정.
F. **학습 전환 도구의 위치.** 안: 상단 바의 작은 드롭다운(현재 학습 이름 ▼). 계획(path, wbs)과 실행(execution) 화면에만 표시하고, 선택은 users.active_goal_id 에 저장한다(기존 PATCH /api/user/profile 사용). 대시보드, 튜터, 자료함에는 표시하지 않는다.

## 6. 개정 (2026-10-22, 화면 확인 피드백 반영)
- 학습 시작일은 사용자가 고른다(월요일 고정 아님). goals.start_date = 사용자가 고른 날짜, 첫 계획 주 plan_week_start = 그 날짜가 속한 주의 월요일(서버가 도출). 일정 구간은 [start_date, target_date]. 상세는 docs/phase5b_fix_instructions_2.md.
- 겹침 안내는 겹치는 학습이 여러 개면 모두 알린다.
