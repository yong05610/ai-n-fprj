# 개발 지시서 — AI 튜터 전용 OpenAI 키 분리

> **대체됨(2026-10-26):** 이 지시서는 개발팀에 전달하지 않는다. 튜터 전용 키는 `docs/phase8c_ai_providers.md` 의 공급자 `openai_tutor` 와 기능별 순서로 흡수되었다(자동 대체 포함). 아래는 기록용이다. 단, 아래 "자동으로 기존 키로 바꿔 다시 시도하지 않는다"는 사용자가 자동 대체를 선택해 더 이상 유효하지 않다(새 문서 §2-3: 공급자 장애에만 대체).

작성: 검증/PM, 2026-10-26. 사용자 결정: **튜터만 별도 OpenAI 키를 쓸 수 있게 분리**한다(비용·사용량을 따로 보고 한도를 따로 두기 위함). 끝나면 `docs/ops_fix_report_tutor_key.md` 로 보고하고 멈춘다. Phase 8B 의 push 와는 별도 커밋으로 하고, push 는 하지 않는다.

## 1. 동작
- 새 환경변수 `OPENAI_API_KEY_TUTOR`(**선택**). 값이 있으면 **튜터 질의에서만** 이 키를 쓴다. 없거나 비어 있으면 기존 `OPENAI_API_KEY` 를 그대로 쓴다(**설정하지 않으면 지금과 동작이 완전히 같아야 한다**).
- "튜터"는 `POST /api/conversations/{id}/messages`(튜터 답변 생성) 하나다. 학습 경로·계획·인사이트·참고자료 수집은 **항상 기존 키**를 쓴다(튜터 키로 새어 나가지 않는다).
- 모델·타임아웃 등 다른 설정은 이번에 분리하지 않는다(`OPENAI_MODEL` 등은 공통).
- 비밀값 규칙: 키 값을 코드·로그·오류 메시지·응답·문서에 쓰지 않는다. 두 키 모두 사용자가 `backend/.env` 와 Render 에 직접 넣는다(개발팀은 값을 만들거나 쓰지 않는다). `/health` 와 오류 응답에 어느 키를 썼는지 노출하지 않는다.
- 배포 가드(`deploy_config.py`)의 필수 비밀값 목록은 **바꾸지 않는다**(튜터 키는 선택).
- 튜터 키가 잘못되어 호출이 실패하면 기존과 같은 AI 오류 응답(`AIUnavailableError` 등 현재 형식)을 낸다. **자동으로 기존 키로 바꿔 다시 시도하지 않는다**(원인을 가리면 안 됨. 어느 키가 문제인지 사용자가 알 수 있도록 로그에 "튜터 키 사용" 여부만 남기고 키 값은 남기지 않는다).

## 2. 구현 방향(개발팀이 정하고 보고)
- `ai_client.py` 에 튜터용 클라이언트를 얻는 의존성(예: `get_tutor_ai_client`)을 두고 `send_message` 만 이를 쓴다. 지금 `get_ai_client` 는 `lru_cache` 로 하나만 만든다. 키 읽기는 **호출 시점**에 하게 해 환경변수를 바꾸면 반영되게 한다(시험 용이).
- 기존 튜터 시험이 `get_ai_client` 를 가짜로 바꾸고 있다. 새 의존성을 쓰면 시험이 깨지므로, 가짜 클라이언트 주입이 두 의존성 모두에 통하게 하거나 시험을 고친다. **기대값은 고치지 않고** 바꾼 시험 목록을 보고한다.

## 3. 시험
- 튜터 키가 있을 때 튜터 호출은 튜터 키로, 같은 요청 안의 다른 호출은 없다(튜터는 AI 1회). 튜터 키가 없으면 기존 키(가짜 OpenAI 클라이언트 생성 인자로 확인).
- 학습 경로·계획·인사이트·ai_topic 수집·링크 제안은 튜터 키가 설정되어 있어도 기존 키를 쓴다.
- 튜터 키 값이 로그, 오류 응답, `/health` 에 나오지 않는다(`caplog`, 응답 문자열 검사).
- 빈 문자열·공백만 있는 튜터 키는 "없음"으로 취급한다.
- 현재 pytest 1251건, 프론트 183건이 그대로 통과한다. 실제 OpenAI 호출은 하지 않는다(가짜 클라이언트).
- `backend/.env.example` 에 `# OPENAI_API_KEY_TUTOR=` 설명 한 줄, `README.md` 환경변수 표(있다면)와 `docs/deploy_guide.md` 의 환경변수 표에는 PM 이 쓴다(개발팀은 `.env.example` 만).
