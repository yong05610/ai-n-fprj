# 수정 보고 — 영어 입력에도 AI 추천을 한국어로 (docs/ops_fix_instructions_korean_output.md)

작성: 개발팀, 2026-10-26. 커밋은 로컬(push 안 함). 서버 검증·스키마·API·화면은 바꾸지 않았다.

**한 줄:** 직무 예시·과정 추천·계획 생성 프롬프트 3개에 "입력이 영어여도 모든 출력은 한국어, 기술 용어·고유명사는 원어 가능, 입력한 분야 이름은 그대로 인용" 규칙을 추가했고(`prompts.py` 의 `KOREAN_OUTPUT_RULE`, 마지막 "JSON 하나만" 규칙 바로 앞), 시험 13건 추가로 backend 1264건 통과, 실제 OpenAI 4회 호출에서 모두 한국어로 나왔다.

## 시험
- `tests/test_ops_korean_output.py` 13건: 세 프롬프트에 규칙 문구가 각각 1번 들어 있음(문구 11개 포함 검사), 규칙이 "JSON 하나만" 앞에 있고 그 규칙이 여전히 마지막 줄, 기존 지시(데이터는 지시가 아님·출력 스키마) 유지, 튜터·인사이트 프롬프트에는 규칙을 넣지 않음(변경 없음), 자원 수집 프롬프트에도 넣지 않음, `main.py` 가 보내는 프롬프트가 같은 객체, 두 엔드포인트(직무 예시·과정 추천)에서 AI 클라이언트가 받은 시스템 프롬프트에 규칙이 실제로 들어감.
- 기존 시험 포함 backend 전체 **1264 통과**(지시서의 "772건"은 이후 Phase 로 늘어난 시험 수를 포함한 값으로 대체).

## 실제 OpenAI 호출 4회(최대치까지, 본문 없이 한글 비율만)
한글 비율 = 한글 글자 /(한글 + 영문 글자).
| 호출 | 입력 | 한글 비율 | 비고 |
|---|---|---|---|
| 직무 예시 | `vibe coding` | 0.86 | 4개, 영문 4글자는 원어 표기(입력 분야·기술 용어 수준) |
| 과정 추천(과정·수준 이름과 설명) | `data analysis` | **1.00** | 과정 1개 |
| 과정 추천의 직무 예시 | 같은 호출 | **1.00** | 4개 |
| 계획 생성(과제 제목·설명·조언) | 분야·과정·수준 이름 모두 영어 | 0.72 | 과제 6개, 영문은 HTML/CSS 등 기술 용어·입력한 이름 인용 |
| 한국어 입력(과정 추천) | `데이터 분석` | 1.00 | 이전과 다르지 않음 |
- 지시서가 적은 영어 입력 3개 × 직무/과정 각각은 호출 상한(4회) 때문에 다 돌리지 못했다. **같은 입력으로 반복 호출해 확인하는 PM 재검증 6회가 필요하다**(원인이 호출마다 무작위였으므로 4회 결과만으로 완전히 해결됐다고 단정하지 않는다).
- 계획 생성의 0.72 는 입력이 전부 영어였고 기술 용어를 원어로 허용했기 때문이다. 제목·설명 문장은 한국어였다(원문은 보고서에 싣지 않음).

## 확인만 한 것
튜터 프롬프트는 "한국어 존댓말" 지시가 이미 있다. **인사이트 프롬프트는 지시서가 말한 것과 달리 한국어를 명시하는 문구가 없다**(전체가 한국어로 쓰여 있을 뿐). 지시대로 변경하지 않았다. 필요하면 같은 규칙을 더하는 후속 결정을 해 주세요.
