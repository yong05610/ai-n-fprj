## 1. 원인 분석 (코드로 확인)

- 사용자 피드백 5번의 "전혀 겹치지 않는데 겹친다"와 2번의 "월요일을 고집할 필요 없음"은 같은 원인이다. 새 학습의 시작일이 "이번 주 월요일"(`mondayOfThisWeekKST()`, LearningPathWizard.tsx 95행)로 기본 설정되고 입력칸 이름도 "계획 주간 시작일 (월요일)"이라 사용자는 시작일이라고 인식하지 못한다. 서버는 [이번 주 월요일, 목표 완료일] 전체를 새 학습의 일정으로 보므로, 새 학습의 완료일이 기존의 먼 미래 학습보다 늦으면 그 학습을 통째로 포함해 겹친다. 예: 기존 학습 (2027-01-25 ~ 2027-01-30)이 있을 때 시작일 기본값 10/19, 완료일 2027-03 이면 겹친다.
- 5-3(돌아가서 일정을 고쳐도 같은 오류)도 같은 원인이다. 사용자는 완료일만 바꿨고 시작일은 고정이라 소용이 없었다.
- 6, 7번(타이머): ExecutionScreen.tsx 의 `timerRunsHere` 는 `timer.task_id === selectedTaskId` 인데, 학습을 전환했다 돌아오거나 새로고침하면 `selectedTaskId` 가 null 로 초기화된다(switchGoal 의 `setSelectedTaskId(null)`). 타이머는 서버에서 계속 진행 중인데 화면은 00:00:00 에 "시작" 상태로 보이고, 시작을 누르면 서버가 이미 진행 중이라고 응답한다.

## 2. 수정 지시

### F1 (필수) 학습 시작일을 사용자가 선택한다
- 마법사의 "계획 주간 시작일 (월요일)" 입력을 "학습 시작일"(아무 날짜, 오늘 이후, 기본값 오늘 KST)로 바꾼다. 월요일 강제 오류 문구와 "이번 주 월요일로 설정" 버튼을 없앤다.
- API: `PlanGenerateRequest`, `PlanConfirmRequest` 에 `start_date`(YYYY-MM-DD)를 추가한다. 서버가 `plan_week_start` = start_date 가 속한 주의 월요일을 clock.py 로 도출한다. 요청의 `plan_week_start` 는 선택으로 남기되 주어지면 start_date 와 모순 없는지 검사하거나 제거한다(DTO 를 바꾸므로 schemas.py, docs/erd_current.md, docs/phase1_design.md, 프론트 타입을 함께 갱신. erd_current.md 의 start_date 설명은 PM 이 이미 수정함).
- 규칙: start_date ≥ 오늘(KST), target_date ≥ start_date(같은 날 허용 여부는 기존 목표일 검증 규칙을 따르되 보고서에 적는다). goals.start_date = 사용자가 고른 날짜. 겹침 검사는 [start_date, target_date].
- 첫 주가 시작일 중간부터인 경우 그 주 앞쪽 요일은 이미 지났거나 시작 전이다. 추천 요일은 마감일이 아니므로 검증하지 않는다. AI 프롬프트에 start_date 를 알려 첫 주 과제량이 시작일 이후 요일에 맞게 배분되도록 하는 것은 이번 범위가 아니다(열린 결정에 적는다).
- start_date 가 없는 기존 클라이언트 요청의 호환: 이번 Phase 에서는 start_date 를 필수로 한다(프론트가 유일한 클라이언트). 기존 테스트의 요청을 갱신한다.

### F2 (필수) 겹침 안내 개선
- 겹치는 학습이 둘 이상이면 모두 알린다. `details` 에 `overlaps: [{goal_id, course, start_date, target_date}, ...]` 를 담고(기존 단일 필드는 호환 위해 첫 항목만 유지해도 됨), 메시지는 "이 기간에 이미 N개의 학습이 있습니다: …" 형식으로 목록을 보여 준다. 사용자 입력 원문을 로그에 남기지 않는다.
- 화면은 안내 문구와 함께 시작일·완료일 입력칸 가까이에 오류를 보여 주고, 날짜를 바꾸면 이전 오류를 지워 다시 저장할 수 있게 한다(현재는 같은 오류가 남아 있는 것처럼 보인다). 겹침 조건을 사용자가 미리 알 수 있게 입력 칸 아래에 "진행 중인 학습과 일정이 겹치면 새 학습을 만들 수 없어요" 한 줄 안내를 둔다.

### F3 (필수) 새로고침과 학습 전환 뒤 진행 중 타이머 표시
- 로드 후 `timer.active` 이고 `timer.goal_id === activeGoalId` 이면 `selectedTaskId` 를 `timer.task_id` 로 자동 선택해, 진행 시간과 "학습 종료" 버튼이 보이게 한다. 새로고침(F5)과 전환 후 복귀 둘 다.
- 타이머가 다른 학습의 것이면 기존 안내 문구를 유지하고, 안내에 "그 학습으로 돌아가기"(전환) 링크를 두는 것은 권장이다.
- 진행 중인 타이머가 있는 상태에서 시작을 눌러 서버가 거부하면(TIMER_ALREADY_ACTIVE 류), 사용자에게는 "이미 진행 중인 타이머가 있어요" 안내와 해당 과제로 이동하는 방법을 보여 준다.
- 테스트: 가능한 범위의 단위 테스트(상태 계산을 순수 함수로 빼서 테스트)를 추가한다. 브라우저에서 확인하지 못한 부분은 보고서에 "미검증"으로 적는다.

### F4 (권장) 마법사 상태 정리
- 저장 성공 후 새 학습을 만들 때 이전 선택(추천 과정, 직무, 수준 등)이 남아 있지 않은지 확인한다(wizardStorage 는 확정 시 clear 하지만, 같은 화면에서 "새 학습 만들기"를 눌렀을 때 React 상태가 초기화되는지는 확인되지 않았다). 사용자 피드백 1번(목록이 종전 등록 내용으로 나옴)이 이것인지 아래 §3 의 질문 답을 받은 뒤 확정한다. 먼저 코드로 재현 시도하고, 재현되면 고친다.

## 추가 지시 (2차, 사용자 피드백 1·3·4번 확정 반영, 같은 보고서에 포함)

### F4 개정 (필수) 학습 목표 입력의 "종전 등록한 목록"은 브라우저 자동완성이다
- 사용자 스크린샷 확인: "학습 목표" 입력칸에 이전에 입력한 값(여행, 자유여행, vibe coding 등)이 말풍선 목록으로 뜬다. 앱이 만든 목록이 아니라 브라우저의 입력 기록 자동완성이다. 앞의 "상태 정리" 가설(React 상태 잔존)은 폐기한다.
- 수정: 마법사의 텍스트 입력(분야, 학습 목표, 과정명 등 자유 입력 전부)에 `autoComplete="off"` 를 둔다.
- 사용자 요구: 목록은 이전 입력이 아니라 **AI 가 위에서 고른 분야 기준으로 추천**해 보여 준다 → F5 로 해결.

### F5 (필수) 마법사 흐름 변경: 분야 → 추천 직무·목표 예시(참고) → 학습 목표 → 세부 과정
- 현재는 직무 chip 이 과정 선택 뒤에 나온다. 사용자 결정: 추천 직무는 **목표를 쓸 때 참고하는 정보**이므로 목표 입력 앞에 나타나야 하고, 그 뒤에 세부 과정 선택으로 간다. 목업(page-path)을 이 흐름으로 수정해 두었다.
- 새 흐름: ① 분야 입력 → ② [대표 직무·목표 예시 보기] 클릭 시 AI 가 직무 chip(참고용)을 제안, 직무 chip 을 누르면 학습 목표 입력칸에 채워진다(수정 가능, 선택 사항) → ③ 학습 목표 입력(선택) → ④ [AI 세부 과정·수준 추천] → 과정 선택 → 수준 → 시간·시작일·완료일 → 계획 생성.
- API: 직무 제안 전용 가벼운 엔드포인트 `POST /api/path/ideas`(입력 field 만, 응답 `suggested_roles: string[]` 3~5개)를 신설한다. 토큰을 아끼기 위해 출력은 이 목록만. 기존 `POST /api/path/recommend` 는 직무를 더 이상 반환하지 않아도 된다(필드는 선택으로 남겨 호환). 서버 검증·재시도·로그 규칙은 기존 AI 호출과 동일(원문 로그 금지, 규칙 위반 시 거부 후 재시도). 개수·길이 규칙을 서버가 검증한다. 호출은 사용자가 버튼을 눌렀을 때만(자동 호출 금지).
- 계획 생성 요청의 `selected_role` 은 그대로 유지한다(직무 chip 을 눌렀다면 전달, 목표 텍스트를 직접 고쳤으면 null 또는 그대로 허용 — 구현에서 선택하고 보고서에 적는다).
- DTO 가 바뀌므로 schemas.py, erd_current.md(영향 없으면 불필요), phase1_design.md API 표, 프론트 타입을 갱신한다. 테스트: 정상, 규칙 위반 재시도, 미동의 403, 가짜 AI 로 개수·길이 검증.
- 실제 OpenAI 호출 확인은 이 엔드포인트 1~2회만(비용). 키 값은 출력하지 않는다.

### F6 (취소) 수준 용어 표기
- 사용자가 최종 결정했다: 화면 라벨은 지금처럼 "현재 수준", "도달 목표 수준"을 유지한다. 라벨을 바꾸지 않는다(이전 F6 문구 변경 지시는 취소, 목업도 원래대로 되돌림). 수준은 사용자 관찰을 보며 이후 조정한다.
- 선택 확인: AI 프롬프트가 수준 이름을 "1단계" 같은 단계명이 아니라 실력을 서술하는 이름으로 짓게 하는지만 읽어 보고, 아니면 보고서의 열린 결정에 적는다(프롬프트 변경 금지).
