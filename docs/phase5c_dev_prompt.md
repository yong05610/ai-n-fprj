# Phase 5C 개발 지시서 — 목업 정렬 (UI)

작성: 검증/PM, 2026-10-22. 끝나면 docs/phase5c_report.md 로 보고하고 멈춘다. Phase 5D 이후는 시작하지 않는다(뼈대도 만들지 않는다).

## 0. 왜 하는가
사용자가 구현 화면을 눌러 보니 표준 목업(mockup/index.html)과 형태가 전혀 달랐다. 지금까지의 지시서는 기능과 내용만 요구했고 앱 틀, 스타일, 배치를 목업대로 맞추라는 말이 없었다(PM 지시 누락, 개발팀 잘못 아님). 이번 Phase 에서 화면 **형태**를 목업에 맞춘다.

**하지 않는 것:** 백엔드, API, DTO, 비즈니스 로직, 기존 테스트 변경. 기존 pytest 258건과 프론트 테스트가 그대로 통과해야 한다. 상태 계산 로직(예: lib/timerSelection.ts)은 그대로 둔다.

## 1. 기준
- **목업을 브라우저에서 열어 나란히 비교하며 작업한다.** file:///C:/Users/ydkim/Desktop/codyssey/ai-n-fprj/mockup/index.html (정적 파일, 서버 불필요). 읽기는 `<style>` 과 `id="page-..."` 섹션 단위로 자른다(한 줄이 길다).
- 판단 기준: 같은 화면을 목업과 구현으로 나란히 놓았을 때 **앱 셸, 영역 구성, 요소 순서, 문구**가 같으면 된다. 목업의 숫자와 이름(Python 개발 기초 33% 등)은 예시 값이므로 실제 데이터를 쓴다.
- **목업 전용이라 가져오지 않는 것:** `.impl-badge`(구현됨·화면 확인 중 등 배지), "목업 예시" kicker, "목업 대화는 이 브라우저에 저장됩니다" 같은 문구, 예시 데이터.
- 기능상 일부러 달라진 것(세부 과정 단일 선택, 편집 가능한 과업 목록, 일정 겹침 안내, 이탈 확인, 동의 거부 화면, 학습 시작일)은 **구현이 맞다.** 목업 쪽은 PM 이 고친다. 목업에 맞추려고 이 기능들을 없애지 않는다.

## 2. 스타일 토큰 (목업 `<style>` 값, 그대로 이식)
- 색: --ink #20263a, --muted #7d8498, --line #e9eaf1, --bg #f6f7fb, --white #fff, --blue #4c62dc, --blue-dark #3549bd, --lav #eef0ff, --purple #8064d7, --green #289b7a, --orange #e7a34b, --red #dc6974
- --shadow 0 10px 30px rgba(39,48,85,.055), --radius 16px
- 본문 14px/1.55, 폰트 Inter, "Noto Sans KR", system-ui. h1 25px, letter-spacing -.8px. 레이블 9~12px 체계(목업 값을 따른다).
- 카드: 흰 배경, 1px --line 테두리, radius 16px, padding 18px. 버튼: 파랑, radius 9px, 11px 굵게. pill: 9px.
- 진행 바 그라디언트(#4b67ed → #8e69ed), 인사이트 카드 배경 그라디언트, 통계 카드 우측 아이콘(✦ ▦ ◷ ↗) 은 목업 CSS 에서 가져온다.
- 구현의 기존 `globals.css` 큰 값(h1 clamp 48px, 카드 radius 24px, padding 48px 등)은 목업 값으로 대체한다. 이미 목업에서 가져온 클래스(goal-row, mini-bars, chip, tab, record-entry, timer-panel)는 수치를 목업 값으로 되돌린다.
- 반응형: 목업의 `@media(max-width:1050px)`, `@media(max-width:720px)`(사이드바 대신 하단 탭바) 를 따른다.

## 3. 작업

### C.1 앱 셸
- 좌측 사이드바 252px sticky, 흰 배경, 오른쪽 1px 선. 위에 로고(PaceMate, LEARN AT YOUR PACE), "사용자" 그룹 메뉴 8개, "관리자 · 미리보기" 그룹 메뉴 6개, 하단 계정 영역(학자 계정, 테스터 미리보기).
- 상단바 68px sticky: breadcrumb("PaceMate / 현재 화면"), 검색창, 오늘 날짜(서비스 시간대 Asia/Seoul, frontend/lib/week.ts 만 사용), 알림 버튼 자리.
- 본문 `.main`: 최대 1500px, 좌우 padding clamp(20px,3vw,42px).
- 현재의 상단 가로 nav 4버튼과 위저드의 "전체 화면 모드(NavBar 숨김)"는 없애고, 모든 화면이 같은 셸 안에서 열린다. 위저드 이탈 확인(confirm)은 유지한다.
- 계정 영역의 "사용자 미리보기" 역할 전환 버튼은 만들지 않는다(관리자 기능은 5E). 계정 영역은 표시만.
- 라우팅: 기존 `View` 상태 방식을 유지해도 되고 App Router 경로로 나눠도 된다. 선택해 보고서에 적는다. 새로고침 후 현재 화면 유지(기존 동작 보존)는 확인한다.

### C.2 메뉴 상태
| 메뉴 | 상태 | 비고 |
|---|---|---|
| 대시보드, 학습 경로 설정, 학습 실행 기록, 종합 학습 분석 | 활성 | 기존 화면 |
| 내 정보·설정 | 활성(최소) | C.5 |
| 학습 과제 계획 | 비활성 + "준비 중" | 5D |
| AI 튜터, 참고자료 보관함 | 비활성 + "준비 중" | Phase 6 |
| 관리자 6개(운영 현황, 사용자 관리, AI 생성 이력, 참고자료 관리, 사용자 피드백, 서비스 설정) | 비활성 + "준비 중" | 5E. 관리자 그룹 제목은 "관리자 · 준비 중"으로 하고, 학습자에게 실제 기능처럼 보이지 않게 한다 |
- 비활성 메뉴는 클릭해도 이동하지 않는다(회색, 작은 "준비 중" pill, `aria-disabled`).

### C.3 대시보드 (page-dashboard)
목업 순서: 헤딩(MY LEARNING SPACE, "안녕하세요, 학습자님 👋", 설명, 우측 "＋ 학습 경로 만들기" 버튼) → 통계 카드 4개(①최근 학습 경로 ②완료 학습 과제 ③이번 주 학습 ④학습 기록, 각 우측 아이콘) → 종합 학습 현황(+ "종합 분석 →" 링크, 안내문) → 2열: 왼쪽 오늘의 추천 과제(과정 요약 카드 + 진행 바 + "전체 일정 보기 →" + 과제 행, 우측 `task-time` 라벨), 오른쪽 AI 학습 인사이트 배너(그라디언트)와 현재 학습 수준 카드 → 주간 활동.
- "AI 튜터에게 물어보기 →", "전체 일정 보기 →" 는 대상 화면이 아직 없으므로 비활성 상태로 둔다(링크 모양 + "준비 중").
- 기존 데이터 필드로 채운다. 목업에 있는 값이 현재 API 에 없으면 **API 를 바꾸지 않고** 그 요소를 숨기거나 기존 값으로 대체하고 보고서에 적는다(예: 현재 학습 수준 카드의 진행 바는 level_progress_text 기반).
- 빈 상태, 로딩, 오류 UI 는 유지한다. "추천 요일은 마감일이 아니다" 안내 문구는 유지한다.
- 대시보드 하단의 데이터 삭제 섹션은 C.5 로 옮긴다.

### C.4 경로 설정, 실행, 분석
- **page-path:** 목업 헤딩 블록(PERSONAL LEARNING PATH, "학습 분야에서 나만의 목표까지", 설명, pill "계획 설정")과 상단 학습 전환 위젯(GoalSwitch)을 추가한다. 2열 카드 구성(왼쪽 입력, 오른쪽 AI 미리보기)과 버튼 문구(✦ 포함)를 목업에 맞춘다. 단일 선택, 편집 가능한 과업, 겹침 안내, 시작일 등 기능은 유지한다. 주간 시간 입력은 숫자 입력 유지(허용 범위 1~100).
- **page-execution:** h1 "학습 실행 기록", kicker STUDY EXECUTION, 설명 문구, 통계 4카드의 레이블·아이콘, 과제 그룹의 진행 바와 상태 pill(완료/진행 중)과 "선택" 버튼을 목업대로. AI 인사이트 카드와 "인사이트 갱신"은 Phase 6.9 에서 하므로 자리만 두고 비활성("준비 중")으로 한다.
- **page-analysis:** 이미 가깝다. h1/h2 수준, 일정 표기(10/05 – 12/28 형식은 기존 표기 유지해도 되나 보고서에 적는다), pill 색을 맞춘다.
- 동의 모달: 문구를 바꾸지 않는다(C.6). 목업과의 문구 차이는 보고서에 목록만 적는다.

### C.5 내 정보·설정 (최소)
- 사이드바 "내 정보·설정" 메뉴에서 열리는 화면을 만들어, 기존 `DeleteDataSection`(모달, 확인, 완료 상태 포함)을 그대로 옮긴다. 동의 안내가 "[내 정보·설정] 메뉴에서 삭제 요청"을 약속하고 있으므로 필수다.
- 목업 page-settings 의 헤딩("내 정보와 개인정보")과 카드 틀만 맞춘다. 프로필 편집, 학습 프로필 카드의 저장 기능, 설문 안내는 Phase 7.3 에서 하므로 이번에는 만들지 않는다(자리나 문구도 넣지 않는다).

## 4. 검증 기준 (PM 이 확인)
- backend pytest 258건, frontend typecheck, npm test, npm run build 전부 통과(실제 건수 보고). 백엔드 파일 diff 가 없어야 한다.
- 화면별 목업 대조표를 보고서에 넣는다(같음/다름/의도적 차이). 브라우저에서 확인하지 못한 항목은 "미검증"으로 적는다.
- 사이드바 비활성 메뉴 클릭 시 이동하지 않음, 활성 메뉴 5개 이동, 새로고침 후 화면 유지, 위저드 진행 중 메뉴 이동 시 이탈 확인.
- 데이터 삭제가 대시보드가 아니라 내 정보·설정에서만 보임.
- 로컬 서버는 AUTH_MODE=dev STORE_BACKEND=memory 환경변수로 덮어써서 빈 포트에 띄운다. `.env` 파일은 수정하지 않는다.
