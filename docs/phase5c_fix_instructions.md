# Phase 5C 수정 지시 — R1 동시 학습 최대 2개 규칙 (PM, 2026-10-22)

사용자 결정으로 일정 겹침 규칙을 고친다. 설계는 docs/multi_goal_design.md §7, docs/erd_current.md "복수 학습 규칙", docs/phase1_design.md 에 이미 반영했다(개발팀은 문서를 고치지 않는다). 끝나면 docs/phase5c_fix_report.md 로 보고하고 멈춘다. Phase 6 은 이 수정이 검증된 뒤 시작한다.

## 1. 왜 바꾸는가
처음 결정문("일정이 겹치는 계획은 2개 이상 만들 수 없다")을 PM 이 "겹치면 무조건 거부"로 풀어 구현 규칙으로 썼다. 사용자 의도는 **같은 날 진행하는 학습은 최대 2개까지 허용하고 2개를 초과(3번째)할 때 거부**하는 것이다. 지금 구현은 같은 기간에 2번째 학습부터 거부해 의도와 다르다.

## 2. R1 (필수) 겹침 검사 규칙 변경
- 새 학습 구간 [start_date, target_date] 의 **어느 하루라도** status=active 인 기존 학습이 **이미 2개** 진행 중이면 409 `GOAL_PERIOD_OVERLAP`. 양 끝 날짜를 포함한다.
- 같은 기간에 기존 학습이 1개면 허용(201). 기존 2개가 있어도 새 학습 기간의 모든 날에 동시에 걸리지 않으면 허용.
- 예: A(10/1~10/31), B(10/10~10/20) 가 있을 때 C(10/12~10/15)는 거부, C(10/21~10/25)는 허용, C(10/1~10/9)는 허용, C(10/9~10/12)는 10/10~10/12 에 2개라 거부.
- 비교 대상은 status=active 만(completed, archived 제외). 기존 학습의 일정 변경은 검사하지 않는다(변경 없음).
- 구현 힌트: 새 구간과 겹치는 기존 학습들의 구간 경계(시작일, 종료일+1)로 날짜를 쪼개 각 조각의 동시 학습 수를 센다. 하루씩 반복하는 방식도 구간이 길지 않으므로 허용하나, 불필요하게 느리지 않게 한다.
- 오류 응답: 메시지는 "한 날에 진행할 수 있는 학습은 최대 2개예요. {conflict_from} ~ {conflict_to} 에 이미 '{A}'({기간}), '{B}'({기간}) 두 학습이 있습니다. 학습 시작일이나 목표 완료일을 조정해 주세요." 형식. `details` 에 `max_concurrent: 2`, `overlaps`(그 구간에 걸린 학습 전부 `{goal_id, course, start_date, target_date}`), `conflict_from`, `conflict_to`(처음으로 2개가 겹치는 연속 구간). 기존 `overlaps` 단일 필드 호환(첫 항목)은 유지한다. 사용자 입력 원문을 로그에 남기지 않는다.
- 호출 경로는 기존과 같다: `POST /api/plan/confirm`, `POST /api/goals`, 입력 검증 이후 저장 직전, plan/confirm 의 멱등 조회는 검사보다 앞.

## 3. 프론트
- 위저드의 안내 문구 "진행 중인 학습과 일정이 겹치면 새 학습을 만들 수 없어요."를 **"같은 기간에 진행할 수 있는 학습은 최대 2개예요."** 로 바꾼다(LearningPathWizard.tsx 696행 부근).
- 오류 표시(702행, 875행 부근)는 서버 메시지를 그대로 보여 주되, 겹치는 학습 목록과 기간이 보이고 날짜를 바꾸면 오류가 지워지는 기존 동작을 유지한다. "일정이 겹쳐 저장하지 못했어요." 문구는 "같은 기간에 이미 학습이 2개 있어 저장하지 못했어요."로 바꾼다.

## 4. 테스트
- 기존 겹침 테스트(test_phase5b_multi.py, test_phase5b_fix2.py, test_phase4_plan.py 의 두 테스트 등) 중 "같은 기간 1개 → 409"를 기대하던 것은 기대값을 새 규칙에 맞게 고친다(바꾼 목록을 보고서에 적는다).
- 신규: 같은 기간 1개 있음 → 201, 같은 기간 2개 있음 → 409(details 에 두 학습, max_concurrent=2, conflict 구간), 2개가 있어도 새 학습이 한쪽 끝만 걸치면 서로 겹치지 않는 날이 있어 허용되는 경우(위 예시 C(10/21~10/25), C(10/1~10/9)), 경계일 포함(하루만 겹쳐도 2개면 거부), completed/archived 는 세지 않음, 타 UID 격리, 과거 시작일은 기존대로 400.
- 프론트: 변경한 문구를 확인하는 테스트가 있다면 갱신한다.
