## 3. 라우팅 방식 선택

기존 `View` 상태 방식을 유지하고 현재 화면을 URL 해시(`#analysis` 등)에 `replaceState` 로 반영한다. 이유: 이전 구현은 새로고침하면 항상 대시보드로 돌아갔다(지시서의 "기존 동작 보존"은 사실상 새로 만드는 동작이었다). 해시 방식은 새 라우트 파일 없이 새로고침 후 화면을 유지하고, 이력(history)을 쌓지 않아 위저드 이탈 확인(앱이 제공하는 모든 이동 수단)이 빠짐없이 적용된다. 브라우저 뒤로가기는 해시를 쓰지 않으므로 화면을 바꾸지 않는다. App Router 경로 분리는 Phase 7 에서 필요하면 재검토.

1. 대시보드 ④ "3개 과제에 기록"(과제 수) → "전체 기간"으로 대체.
2. 현재 학습 수준 카드의 진행 바와 "수준 변경" 링크 → 숨김.
3. 오늘의 추천 과제 카드의 주차 주제 제목 → 과정명으로 대체.
4. 실행 화면 과제 그룹의 "과제 완료 처리" 링크, 기록 행 "기록" pill → 생략.

## 6. 열린 결정

1. 위의 "과제 완료 처리"를 실행 화면에도 둘지(기능 추가이므로 별도 지시 필요).
2. 설정 화면 카드 제목을 목업의 "데이터와 AI 사용"으로 맞출지. 현재 삭제 설명 문구와 어울리게 "내 학습 데이터 삭제"로 두었다.
3. 상단 검색창은 메뉴 이름 검색만 한다. "학습 검색"까지 필요한지.
4. 실행 화면 통계 "주 목표 N분"은 기존 계산(이번 주 과제 예상 시간의 합)이다. 목업의 값(주당 가능 시간 × 60)과 다를 수 있다(5C 범위 밖이라 계산은 건드리지 않음).
5. App Router 경로 분리 여부(위 3번).

## 7. 미검증
