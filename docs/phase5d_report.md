## 4. advice 의 한계 (지시서 §4 요구)

- 저장되는 조언 텍스트는 **클라이언트가 보낸 값**이다. 서버는 이 텍스트가 실제 AI 결과인지 재검증할 수 없다(길이·공백·둘 다 있어야 함만 검사). 사용자가 직접 API 를 호출해 임의의 조언 글을 자기 목표에 저장할 수 있지만, 그 글은 **본인 UID 의 본인 화면에만** 쓰인다.
- 표시는 React 가 이스케이프하며(HTML 로 해석하지 않음), 로그에는 남기지 않는다(테스트: 로깅을 켠 상태에서 제목·내용이 로그에 없음, 실서버 로그 검색도 0건).
- 그래서 "AI 생성 · 참고용" 표시는 조언이 저장된 목표에만 붙고, 조언이 없는 기존 목표는 고정 안내문(AI 표시 없음)을 쓴다.

| 요소 | 결과 |
|---|---|

| 왼쪽 큰 카드 제목(과정명), 부제 "현재 … → 목표 … · 주 N시간" | 같음(수준 번호는 표시하지 않음) |

## 6. 브라우저 확인 (Chrome 자동 스크립트 + 캡처, 전부 통과)

학습 2개를 만들고(A: 조언 저장·참고자료 있음·주 3개 + 다른 두 주에 과제, B: 조언 없음·자료 없는 분야) 확인:
- 처음 열면 이번 주(Asia/Seoul)가 보임, 새로고침 후 `#wbs` 유지, 학습이 없는 사용자는 안내와 "학습 경로 설정으로 이동" 링크(클릭하면 이동).
- 요일 변경 → "저장 중…" 후 "계획 저장됨 ✓", 서버 값 확인, **새로고침 후 유지**. 완료된 과제의 요일도 변경됨.
- **연속 변경(월→화→토, 응답을 일부러 지연):** 서버에 `월, 토` 순서로 한 번에 하나씩만 전송되고 최종 서버 값 = 화면 값 = 토. (중간 값 "화"는 건너뜀.)
- **오류(503 가로채기):** 버튼이 "저장하지 못했어요. 다시 시도"로 바뀌고 오류 문구가 뜨며 드롭다운은 사용자가 고른 값을 유지. 가로채기를 풀고 버튼을 누르면 마지막 선택이 전송되어 서버와 같아지고 "계획 저장됨 ✓"로 복귀.
- 주 이동: 이번 주 → 다음 주("다음 주") → 빈 주를 건너뛰어 "3주 뒤"(다음 버튼 비활성) → 돌아오면 이번 주(이전 버튼 비활성). 화면 전체에 연체·지연 표현 없음.
- 학습 전환: B 의 계획이 보이고(과제 1개), 조언 카드는 고정 안내문 + AI 표시 없음, 참고자료 카드는 "사전 검토 자료를 찾지 못했습니다" 안내(자료 항목 없음), 전환이 현재 학습으로 저장됨, A 로 돌아오면 다시 이번 주.
- 위저드에서 확정한 계획의 조언이 저장되어 이 화면에 "AI 생성 · 참고용"과 함께 보임(확정 직전 초안을 복원해 저장 버튼을 눌러 확인, AI 호출 없음).
- 메뉴: 활성 화면 이동, 비활성 메뉴 7개(보관함 + 관리자 6) 그대로. 페이지 오류 없음.

## 8. 열린 결정

1. **참고자료 카드의 안내문 문구.** `references_notice` 는 plan/generate 용으로 쓰던 문장이라 끝에 "아래 계획은 등록 자료 없이 AI가 생성한 일반 계획입니다."가 붙어 있다. 지시서대로 그대로 보여 주었지만 이 화면에서는 "아래 계획"이 어색하다. 문구를 화면용으로 나눌지(서버 변경) 결정이 필요하다.
2. `source_name` 추가(§3)를 그대로 둘지. 대안은 분류만 표시하는 것.
3. 계획 주 범위: 과제가 있는 주 사이에서만 이동한다(빈 주는 건너뜀). 계획에 구멍이 있는 학습(예: 3주 뒤 과제)에서는 "다음 주" 버튼이 몇 주를 건너뛰므로 pill 에서 "3주 뒤"처럼 몇 주 뒤인지 보이게 했다.
4. 저장 중 화면을 떠나면(다른 메뉴로 이동) 진행 중인 요청은 끝까지 전송되지만 결과 표시는 없다. 이번에는 이탈 확인을 만들지 않았다.
5. 요일 변경이 화면에서 한 번 실패한 뒤 그 과제를 다시 바꾸면 이전 실패는 새 값으로 대체된다(마지막 값 우선). 다른 과제의 실패는 그대로 남아 "다시 시도"로 재전송된다.
