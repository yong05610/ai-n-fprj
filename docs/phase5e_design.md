# Phase 5E 설계 — 관리자(사용자 관리·피드백)

결정: 2026-10-22 사용자 승인. 구현은 Phase 6(튜터), 5D 뒤에 시작한다(개발 지시서 docs/phase5e_dev_prompt.md 는 그때 PM 이 쓴다). 이 문서는 설계 기준이다.

## 1. 범위
- 구현: 관리자 식별, 사용자 관리 화면, 피드백 수집(학습자), 피드백 관리 화면(관리자).
- 제목과 "준비 중"만: 운영 현황, AI 생성 이력, 참고자료 관리, 서비스 설정.
- 목적: 사용자 테스트(Phase 8) 운영. 외부 익명 설문(PRD FR-07)은 그대로 병행할 수 있다.

## 2. 관리자 식별
- 환경변수 `ADMIN_UIDS`(쉼표 구분 Firebase UID). 코드와 문서에 UID 값을 쓰지 않는다. 설정은 사용자가 backend/.env 와 Render 환경변수에 직접 한다.
- `require_admin_uid` 의존성: ID 토큰의 UID 가 목록에 있을 때만 통과, 아니면 403(ErrorResponse). 요청 본문, 헤더, 쿼리의 어떤 값도 관리자 판단에 쓰지 않는다. 관리자도 평소 사용자이므로 동의 전제(require_consented_uid)는 그대로 거친다.
- `GET /api/user/profile` 응답에 `is_admin: bool`(읽기 전용, 수정 불가)을 추가한다. 프론트는 이 값으로 관리자 메뉴 그룹을 보인다. **관리자가 아닌 사용자에게는 관리자 그룹을 숨긴다**(5C 에서는 모두에게 "준비 중"으로 보이던 것을 5E 에서 정리).
- 익명 UID 는 브라우저 저장소를 지우면 바뀐다. 관리자는 [내 정보·설정]에서 자기 계정 ID 를 복사해 허용 목록에 넣는다(설정 화면에 "관리자 등록용 계정 ID 복사" 버튼, 본인에게만 보임). 운영 안내를 docs/firebase_setup_guide.md 에 추가한다.
- dev 모드의 `dev-<uid>` 토큰도 같은 로직을 쓴다(테스트 가능).

## 3. 사용자 관리 (page-admin-users)
`GET /api/admin/users?status=all|active|dormant` (관리자 전용, 페이지당 50건, 최근 활동순).
| 열 | 값 | 비고 |
|---|---|---|
| 사용자 ID | 마스킹된 UID(앞 4자 + •••) | 전체 UID 는 내려 주지 않는다 |
| 유형 | 익명 | 이메일 유형은 만들지 않는다 |
| 동의 | 동의함/안 함, consent_version | |
| 진행 중 학습 | 개수 | 과정명, 목표 내용, 회고, 대화는 내려 주지 않는다 |
| 최근 활동 | users.last_active_at | |
| 상태 | 활성(최근 7일 활동) / 휴면 | 기준일은 서비스 시간대 Asia/Seoul, clock.py 사용 |
- 개인 식별 정보와 학습 내용은 보여 주지 않는다. 사용자 삭제 요청은 즉시 처리되어 사용자가 목록에서 사라지므로 "삭제 요청" 열은 만들지 않는다(목업 수정).
- 읽기 전용 화면이다. 관리자가 사용자 데이터를 수정하거나 삭제하는 기능은 만들지 않는다.

## 4. 피드백
### 4.1 수집 (학습자)
- 위치: [내 정보·설정] 안의 "테스트 피드백" 카드.
- `POST /api/feedback` (require_consented_uid): `{usability: 1~5, ai_usefulness: 1~5, screen: dashboard|path|execution|analysis|settings|other, comment?: 1000자 이하, client_request_id}`.
- **저장하지 않는 것:** user_id, UID, 토큰, 연락처. 서버는 UID 로 인증만 하고 피드백 문서에 연결하지 않는다.
- 멱등: client_request_id(무작위) 로 중복 제출 방지(UID 와 무관한 값).
- 남용 방지: users 문서의 `feedback_submitted_count` 가 10 을 넘으면 429(내용과 연결 없음, 데이터 삭제 시 함께 사라지는 것은 허용).
- 의견 원문을 로그에 남기지 않는다. 오류 메시지에도 포함하지 않는다.
- 안내: "피드백에는 사용자 정보가 저장되지 않아 제출 후 삭제 요청으로 지울 수 없어요."를 입력 칸 아래에 표시한다.

### 4.2 관리 (관리자, page-admin-feedback)
- `GET /api/admin/feedback?status=&limit=` 목록(최신순, 최대 200)과 `GET /api/admin/feedback/summary`(미확인 건수, 사용성 평균·응답 수, AI 유용성 평균·응답 수, 개선 후보 수, 반영 완료 수(최근 30일)).
- `PATCH /api/admin/feedback/{id}` `{status: seen|candidate|done}` 상태만 변경한다. 의견 수정, 삭제 기능은 만들지 않는다.
- 목업의 "AI 튜터 · 익명 테스터 · 유용성 3/5" 표기를 따른다(화면·점수만).

## 5. 동의 안내(동의 모달) 변경
- "데이터 삭제" 항목 아래에 한 항목을 추가한다: "테스트 피드백을 제출하면 사용자 정보 없이 저장되어, 이후 삭제 요청으로 지울 수 없습니다. 피드백 제출은 선택입니다."
- 이는 개인정보 관련 문구 변경이므로 **약관 버전을 v1.1 로 올린다**(CURRENT_TERMS_VERSION). 기존 v1.0 동의자는 재동의가 필요하다. 현재 사용자는 개발·검증 테스트 계정뿐이라 영향이 작다. 5E 개발 지시서에서 재동의 흐름(이미 구현된 버전 비교)이 동작하는지 확인하게 한다.
- 문구 확정은 PM 이 하고 목업과 구현을 함께 고친다.

## 6. 보안·검증 기준 (5E 지시서에 포함)
- 비관리자가 `/api/admin/*` 호출 시 403, 토큰 없음 401.
- 요청에 `is_admin`, `role` 을 실어 보내도 무시된다.
- 피드백 문서에 UID 관련 필드가 없음(저장 문서 검사 테스트).
- delete-data 후에도 피드백은 남고, 사용자 문서는 지워짐.
- 관리자 목록 응답에 전체 UID, 과정명, 회고가 없음.
- Firebase 실연동 확인과 화면 확인은 사용자 몫.

## 7. 열린 항목
- 관리자 UID 확인 방법(복사 버튼)을 사용자가 불편해하면 보완.
- 피드백 목록이 200건을 넘는 경우의 페이지 처리(MVP 에서는 5명 이상 규모라 제외).
