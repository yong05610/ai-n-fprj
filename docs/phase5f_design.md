# Phase 5F 설계 — 전체 학습 과정 일괄 계획 (2026-10-25)

결정자: 사용자(2026-10-25). 작성: 검증/PM. 개선 이력: docs/ai_improvement_log.md IMP-008.

## 1. 왜 바꾸는가
지금은 AI 가 "첫 주 한 주치" 과제(3~6개)만 만들고 확정 때 시작 주 하나에만 저장한다. 그 뒤 주부터 목표 완료일까지는 계획이 없고 자동 반복도 없다(사용자가 계획 화면을 보고 "주간 계획이라고만 나오는데 이 세트가 종료 때까지 반복되는 것이냐"고 질문해 확인, 코드 확인으로 첫 주만 있음을 확인). 학습은 1장, 2장, 3장을 **한 번 순서대로 지나가는 것**이지 매주 같은 세트를 되풀이하는 것이 아니다. 따라서 전체 과정을 한 번에 계획한다.

## 2. 사용자 결정 사항
1. 모든 과정(과제)을 일괄 계획한다. 화면에는 총 소요 시간과 이번 주(또는 오늘) 학습 예정 시간을 보여 준다.
2. **과제 한 개의 시간에 상한을 두지 않는다.** 과제 시간은 학습자의 현재 수준과 목표 수준 차이에 따라 AI 가 정한다. 따라서 한 과제가 한 주를 넘을 수 있다.
3. 기존 학습(첫 주만 있는 계획)은 호환하지 않고 새로 만든다. 단, 읽기 코드는 새 필드가 없는 과제도 오류 없이 처리한다(개발·테스트 계정 보호).

## 3. 설계 요약
**역할 분담 (6B 교훈: 계산은 서버, 판단은 AI)**
- AI: 무엇을, 어떤 순서로, 각각 몇 분인지만 정한다. 출력은 순서 있는 과제 목록(제목, 설명, 예상 분)과 조언. 주차·요일·합계 계산을 시키지 않는다.
- 서버: 가용 시간 계산, 총합 검증, 제목 중복 검증, 주차 배치, 추천 요일 기본값 계산.

**가용 시간(예산)**
- 주 수 N = 시작일이 속한 주(월요일 기준)부터 목표 완료 희망일이 속한 주까지의 주 수(양 끝 포함, `clock.py`).
- 가용 분 = 주당 가능 분(weekly_hours × 60) × N. 총 예상 시간은 가용 분 이하여야 한다. **일찍 끝나는 것은 허용**하며 시간을 채우려고 늘리지 않는다.

**주차 배치 (결정적 계산)**
- 과제를 순서대로 타임라인에 이어 붙인다. 과제 i 의 시작 위치 = 앞선 과제들의 예상 분 합 = `timeline_start_minutes`.
- 시작 주 = `floor(timeline_start_minutes / 주당 분)`(0 이면 시작 주, 1 이면 다음 주).
- 한 주 k(0부터)는 구간 `[k × 주당 분, (k+1) × 주당 분)`. 과제는 자기 구간 `[start, start + 분)` 과 겹치는 모든 주에 나타난다. 어떤 주의 **예정 분** = 그 주 구간과 과제 구간이 겹치는 길이의 합(주당 분을 넘지 않는다). 한 과제가 여러 주에 걸치면 각 주에 "이어서(이번 주 N분 / 총 M분)"로 표시한다.
- 예(주당 300분): 1장 120(0~120) → 2장 90(120~210) → 3장 150(210~360, 1주차 90분 + 2주차 60분) → 4장 240(360~600, 2주차 240분). 1주차 예정 300분, 2주차 300분.
- 마지막 주의 끝은 목표 완료일이 속한 주이며, 총합 ≤ 가용 분이므로 그 안에서 끝난다.

**추천 요일 기본값(서버)**: 과제가 시작하는 주 안에서의 위치 `(start mod 주당 분) / 주당 분`(0 이상 1 미만)에 7 을 곱해 내림한 값을 월~일(0~6)로 쓴다. 사용자가 바꿀 수 있고(5D 화면) 마감일이 아니다. AI 는 요일을 내지 않는다.

**오늘 예정 시간**: 오늘이 속한 주에 예정 분이 있는 과제 중 추천 요일이 오늘인 과제의 이번 주 예정 분 합. 해당 과제가 없으면 "오늘 추천 과제 없음"이 아니라 이번 주 미완료 과제 중 다음 순서 과제를 제안하는 기존 대시보드 규칙(PRD FR-06)을 따른다.

**확정 후**: 확정 때 서버가 배치를 계산해 저장하고(`plan_week_start`, `timeline_start_minutes`, `suggested_weekday`), 이후 일정은 고정이다. 과제 시간을 나중에 바꿔도 이후 과제를 다시 배치하지 않는다(후속 개선 후보).

## 4. 영향 범위
- 백엔드: 계획 생성 프롬프트·스키마·검증(전체 과정), 확정 처리(서버 배치 저장), 주간 시간 예산 검증 규칙(주 단위 → 목표 전체 가용 시간 단위), 대시보드 오늘/이번 주 계산, 읽기 호환.
- 프론트: 위저드 미리보기(총 시간과 가용 시간, 주차별 그룹, 과제 수정 시 즉시 재배치 표시), 주간 계획 화면(전체 주 이동, "이어서" 표시, 총 소요 시간), 대시보드(이번 주·오늘 예정 시간).
- 데이터: `tasks.timeline_start_minutes` 추가(erd_current.md 갱신됨). PRD FR-02 갱신됨.
- 영향 없음: 추천 요일은 마감일이 아니다(연체·실패·이월 없음), 진행률 = 완료 과제 수 / 전체 과제 수, 복수 학습 규칙(R1), 6B 인사이트, 튜터.

## 5. 한도와 위험
- 과제 수 3~60개, 한 과제 1~6000분(기존 스키마 한도). 과제 제목은 공백·대소문자를 정리해 서로 달라야 한다(같은 과제 반복 금지).
- AI 응답이 길어져(최대 60개 과제) 지연·형식 오류가 늘 수 있다. 개발팀이 실제 호출로 지연을 측정해 보고하고, 타임아웃이 부족하면 설정만 조정한다(구조 변경은 PM 협의).
- 기간이 매우 길고 주당 시간이 많으면 가용 시간이 커지지만, AI 는 필요한 만큼만 계획하면 된다(채우지 않음). 학습 범위가 가용 시간보다 크면 과제 시간을 줄이거나 범위를 줄이도록 프롬프트에 명시한다.
