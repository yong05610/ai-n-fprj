## 2. 발견한 문제 (수정 지시서 R1, R2)
- **R1 가용 시간 과대 계산(개발팀 질문의 답):** 시작일이 일요일, 목표일이 60일 뒤이면 실제 61일(8.7주)인데 가용이 10주분(3000분)으로 약 15% 크다. 시작일이 속한 주와 목표일이 속한 주를 통째로 세기 때문이다. 결정: 가용 시간 = floor(주당 분 × 포함 일수 / 7), 주차 배치는 그대로.
- **R2 긴 기간에서 계획이 얇음(실제 AI):** 26주·주 15시간(가용 23400분)에서 AI 가 과제 10개, 총 3600분(15%)만 만들었다. 짧은 기간(개발팀 측정 62~92%)과 달리 기간이 길수록 비율이 작다. 서버 강제 대신 프롬프트 보강, 응답에 `coverage_percent`, 위저드의 중립적 안내, 개발팀의 실제 AI 3회 측정으로 대응하고, 효과가 작으면 PM 이 하한 검증을 판단한다.
- 참고(결함 아님): 생성 결과의 과제가 모두 정확히 300분이라 추천 요일이 전부 mon 이 되었다. 요일 기본값이 주 안의 시작 위치에만 의존하기 때문이며, 과제가 한 주를 정확히 채우면 자연스러운 결과다.

## 5. 사용자가 직접 눌러 볼 항목
1. 새 학습 만들기 → 계획 단계에서 **총 예상 시간과 가용 시간**, 주차별로 묶인 과제 목록이 보이는가.
2. 과제 시간을 바꾸거나 삭제했을 때 주차 배치가 **즉시** 다시 계산되어 보이는가(확정 전). 제목을 중복으로 입력하면 오류가 나는가.
3. 한 주를 넘는 과제가 **"이어서 N주에 걸쳐 진행"** 으로 시작 주에 표시되고, 이어지는 주에도 "이어서(이번 주 N분 / 총 M분)"로 보이는가.
4. 확정 후 주간 계획 화면에서 첫 주부터 마지막 주까지 이동할 수 있고 요일 변경이 저장되는가. 연체·지연 표현이 없는가.
5. 대시보드에 "이번 주 예정", "오늘 예정" 시간이 보이는가.
6. (R1, R2 수정 뒤) 요약의 총 일수와 가용 시간, 얇은 계획 안내.
