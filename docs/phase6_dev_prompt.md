## 1. 자료(RAG) 준비 — 6.1
현재 backend/data/rag_documents.json 은 자료 10건의 메타데이터(제목, 출처, URL, 라이선스)만 있고 모든 `chunks` 가 비어 있다. 튜터가 쓸 본문 조각이 없으므로 먼저 만든다.
- 개발팀이 문서당 4~6개, 조각당 300자 안팎의 **짧은 요약 조각**을 한국어로 직접 쓴다. 공식 문서 원문을 그대로 복사하지 않는다(라이선스: CC BY-NC-SA 등). 각 조각은 해당 자료의 실제 내용과 맞아야 하며 지어내지 않는다. 조각 필드: `id`(예: doc_001_c1), `text`, `keywords`(5개 내외), `verified: false`.
- **검증 흐름:** 조각은 `verified: false` 로 저장하고 서버는 `verified: true` 인 조각만 검색에 쓴다. PM 이 내용을 검토해 승인 목록(docs/phase6_chunk_review.md)을 남기면 그 뒤 개발팀이 승인된 조각만 `verified: true` 로 바꾼다. 검토 전에도 개발과 테스트는 테스트용 가짜 조각으로 진행한다.
- 검색: 임베딩이나 외부 호출 없이 어휘 기반으로 한다. 질문과 조각의 토큰(기존 resources_catalog 의 한글·영문 토큰 분리 방식 재사용) 겹침과 keywords 가중치로 점수를 매겨 상위 3개를 고른다. 임계값 미만이면 "검색 결과 없음"이다. 읽기 전용이며 사용자 입력을 인덱스에 쓰지 않는다. 점수·임계값 규칙을 보고서에 문서화한다.
- 검색 결과가 없으면 **자료 기반 답변이 아님**을 답변과 화면에 밝히고 출처를 만들지 않는다(6.3).

## 2. 백엔드 API — 6.4~6.6, 6.8
- `GET /api/data/summary` 는 이미 있다(키워드로 일치 회고 우선, 최근 회고 최대 5건). 현재 동작이 TASK 6.4 와 맞는지 읽고 확인하며, 회고를 수정하면 최신 내용, 삭제하면 이후 조회에서 제외되는지(6.8) 테스트로 보인다. 튜터 호출은 이 함수의 내부 로직을 재사용한다(HTTP 로 자기 자신을 부르지 않는다). 진행 중인 **모든 학습**이 대상이다(active_goal_id 한정 아님).
- 대화 API (모두 require_consented_uid, 소유권은 토큰 UID 로 검사, 타 UID 는 403):
  - `POST /api/conversations` → 새 세션(빈 대화, 제목은 "새 대화").
  - `GET /api/conversations` → 최근 갱신순 목록. 항목은 id, title, created_at, updated_at 만(messages 제외). 최대 50건.
  - `GET /api/conversations/{id}` → 메시지 전체(role, content, timestamp, 그리고 assistant 메시지의 `sources`: [{doc_id, title, source_name, url}]).
  - `POST /api/conversations/{id}/messages` `{content(1~1000자), client_request_id}` → 같은 `client_request_id` 로 재요청하면 중복 저장 없이 기존 결과를 돌려준다(멱등).
- 메시지 처리 순서: 요약 조회(본인 UID, 모든 진행 중 학습, 최근 회고) → 자료 검색(상위 3개) → 시스템 프롬프트 구성 → **AI 한 번 호출** → 서버 검증 → user·assistant 메시지 저장 → 첫 질문이면 제목 설정(첫 질문의 앞 30자, AI 추가 호출 없음) → updated_at 갱신.
- **질문 필터(학습 관련 판정):** 별도 분류 호출을 하지 않고 한 번의 구조화 출력 `{relevant: bool, answer: str, used_source_ids: [str]}` 로 처리한다. 진행 중인 모든 학습과 학습 방법·요령에 관한 질문은 relevant=true. 학습과 무관한 질문(잡담, 학습 외 정보 요청 등)은 relevant=false 이며 서버가 고정 거절 문구("학습과 관련된 질문에만 답할 수 있어요. …")를 답변으로 저장한다(AI 가 쓴 답은 버린다). 관련 있는 질문이 거절된 경우 사용자가 다시 물을 수 있게 안내 문구에 포함한다.
- **서버 검증:** 스키마, answer 길이(1~2000자), used_source_ids 는 이번에 검색된 조각의 doc 안에 있어야 한다(없는 출처 금지). 위반하면 조용히 고치지 않고 재시도(기존 AIClient.generate 의 validator 와 MAX_RETRIES 사용), 끝내 실패하면 기존 AI 오류 응답 형식으로 돌려준다. 자료가 검색되지 않았는데 used_source_ids 가 있으면 위반이다.
- **실패 시:** 메시지는 성공했을 때만 저장한다(user, assistant 한 쌍). 실패하면 아무것도 저장하지 않고 오류를 돌려주며 프론트가 입력을 보존해 재시도한다.
- **프롬프트 안전:** 사용자 질문과 회고는 JSON 데이터로 전달하고 그 안의 어떤 지시도 따르지 않는다(기존 prompts.py 규칙 형식을 따른다). AI 는 자료에 없는 내용을 자료에서 인용한 것처럼 쓰지 않는다. 컨텍스트로 보내는 이전 대화는 최근 10개 메시지까지.
- 대화는 USER_OWNED_COLLECTIONS 에 이미 있어 데이터 삭제 요청 때 함께 지워진다. 목표 삭제는 대화를 지우지 않는다.
- 로그: 질문, 답변, 회고 내용, AI 원문, 토큰을 남기지 않는다. 오류 메시지에도 포함하지 않는다.

## 3. 프론트 — 6.7, 6.10 (page-tutor 레이아웃)
- 사이드바의 "AI 튜터" 메뉴를 활성화한다. 5C 에서 "준비 중"이던 대시보드의 "AI 튜터에게 물어보기 →" 링크도 튜터 화면으로 연결한다. 다른 비활성 메뉴는 그대로 둔다.
- 목업 구성: 헤딩(AI STUDY TUTOR, "학습 질문과 답변", 설명, pill "자료 검색 + 내 회고") → 안내 문구("진행 중인 모든 학습과 학습 방법·요령에 관한 질문에 답해요. 학습과 관련 없는 질문에는 답변하지 않습니다.") → 좌측: 대화 기록 패널(최근 대화 목록, "＋ 새 대화")과 메시지 영역, 입력창과 "보내기", 하단 AI 안내("AI가 생성한 설명은 참고용이며, 정확성과 출처를 확인해 주세요.") → 우측 "답변 참고 정보": 학습 요약(진행 중 학습의 과정명, 현재·목표 수준), 최근 회고, 참고자료(제목, 출처, "원문 보기 ↗"), 안내("요약과 회고는 본인 UID의 기록만 사용합니다.").
- 응답 대기 중 입력 비활성과 진행 표시, 오류 시 입력 유지 + 다시 시도 버튼, 빈 상태(대화 없음, 자료 없음 안내 "참고한 자료가 없어요. 일반적인 학습 조언이에요."). 모든 AI 답변에 AI 생성 안내를 표시한다(6.10).
- **새로고침 후 복원:** 현재 대화 id 는 URL 해시에 둔다(예: `#tutor/<conversation_id>`). 새로고침해도 대화 목록과 현재 대화가 복원된다. 해시의 id 가 다른 사용자의 것이거나 없으면 오류 없이 새 대화 화면으로 간다.
- 날짜 표기는 frontend/lib/week.ts 만 쓴다.

## 4. 테스트와 확인
- backend: 기존 258건(R1 이후 건수 유지) + 신규. 항목: 자료 있음/없음 질문 구분(없을 때 출처 없음과 안내), 무관 질문 거절, 규칙 위반(없는 출처) 재시도와 실패, 타 UID 접근 403, 목록에 messages 없음, 멱등 재요청 중복 없음, 미동의 403, 제목 생성, 회고 수정·삭제 반영, 실패 시 저장 없음, 모든 진행 중 학습이 요약 대상, 로그에 질문·답변 원문 없음(가능한 범위). 가짜 AI 로 검증한다.
- frontend: typecheck, npm test(해시 파싱과 상태 계산 같은 순수 로직), build.
- 실제 서버: 빈 포트, AUTH_MODE=dev STORE_BACKEND=memory 환경변수 덮어쓰기(`.env` 수정 금지). **실제 OpenAI 호출은 2~3회만**(자료 있는 질문, 자료 없는 질문, 무관 질문 각 1회). 키 값은 출력하지 않는다.
- 브라우저: 새 대화 → 질문 → 답변과 출처 → 새로고침 후 복원 → 목록에서 이전 대화 선택 → 오류 후 재시도. 확인하지 못한 것은 "미검증"으로 적는다.
