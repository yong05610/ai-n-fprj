## 2. 자료(RAG) — 6.1~6.3

**조각 파일:** `backend/data/rag_chunks.json` (신규). `rag_documents.json` 은 수정하지 않았다(PM 판단: 별도 파일, 자료 id 로 연결). 10개 문서 × 5~6조각 = **53조각**. 필드: `id`(예 `doc_001_c1`), `text`, `keywords`(5개 내외), `verified: false`. 공식 문서 원문을 복사하지 않고 한국어로 요약했으며, 확실히 아는 일반 사실만 썼다.

| 문서 | 조각 | 문서 | 조각 |
|---|---|---|---|
| doc_001 Python 기본 문법 | 5 | doc_006 SQL 기초 | 6 |
| doc_002 Python 자료구조 | 6 | doc_007 Git | 5 |
| doc_003 Python 함수 | 5 | doc_008 Next.js App Router | 5 |
| doc_004 JS 기초(MDN) | 5 | doc_009 FastAPI | 6 |
| doc_005 비동기 JS(MDN) | 5 | doc_010 javascript.info | 5 |

- **지시와 다른 점:** 조각 길이가 113~206자(평균 약 170자)로 지시서의 "300자 안팎"보다 짧다. 문장을 늘리면 틀린 내용이 섞일 위험이 커져 정확성을 우선했다. PM 이 더 긴 조각을 원하면 말해 주면 늘린다. 문서당 조각 수는 4~6 범위 안(실제 5~6)이다.
- **검증 흐름:** 서버는 `verified: true` 인 조각만 검색한다. 지금은 53조각이 모두 `false` 이므로 **PM 이 `docs/phase6_chunk_review.md` 로 승인하기 전에는 튜터는 항상 "참고한 등록 자료가 없어요" 상태로 답한다**(동작은 정상, 근거 없는 출처를 만들지 않음). 승인 후 개발팀이 승인된 id 만 `true` 로 바꾼다. 실제 호출 확인은 `RAG_CHUNKS_PATH` 환경변수로 가리킨 **임시 복사본**(전부 true)으로 했고, 저장소의 파일은 바뀌지 않았다.
- **검색 규칙(코드: `backend/rag.py`, 임베딩·외부 호출·사용자 입력 인덱싱 없음):**
  1. 토큰: 영문·숫자 연속과 한글 연속(resources_catalog 와 같은 분리), 소문자. 주제 없는 질문어(어떻게, 알려줘, 설명 등)와 1글자 토큰은 무시.
  2. 두 토큰이 같거나, 한쪽이 다른 쪽으로 시작하고 짧은 쪽이 한글 2자 이상·영문 4자 이상이면 일치(조사 "리스트에서"~"리스트", 복수형 "functions"~"function").
  3. 조각 점수 = 질문의 서로 다른 토큰마다, 조각 `keywords` 토큰과 일치하면 +3, 아니면 본문 토큰과 일치하면 +1.
  4. **임계값 3 이상**(키워드 1개 또는 본문 3개 일치)인 조각만 후보. 점수 내림차순(동점은 조각 id)으로 **상위 3개**. 임계값 미만이면 검색 결과 없음.
  5. 결과가 없으면 답변 끝에 서버가 "※ 참고한 등록 자료가 없어요. 일반적인 학습 조언이에요."를 붙이고 출처 목록은 비운다.
  - 샘플 11문장 확인(`verified` 복사본): 자료 질문 9건은 맞는 문서가 결과에 들어왔고(SQL 문장은 아래 동점 문제로 일부 조각만), 일반 학습 질문과 무관 질문 2건은 빈 결과. **알려진 한계:** 점수가 같은 조각이 4개 이상이면 id 순으로 3개만 남아 가장 알맞은 조각이 빠질 수 있다(예: "WHERE 와 JOIN 차이" 에서 JOIN 조각 누락). 조각 수가 늘면 조정 대상.

## 3. 백엔드 API — 6.4~6.8

| API | 동작 |
|---|---|
| `GET /api/data/summary?keywords=` | **지시서는 "이미 있다"고 했지만 실제로는 `_not_implemented()` 스텁이어서 이번에 구현했다.** 진행 중(active)인 **모든 학습**의 요약(`learning_summary`, 한 줄에 한 학습: "분야 · 과정 \| 현재 X → 목표 Y \| 진행률 n% (a/b개 과제)")과 최근 회고 최대 5건. 진행 중 학습의 과제 회고만 대상. `keywords`(최대 200자)와 일치하는 회고가 먼저, 나머지는 최신순(학습일, 작성 시각). 매 호출마다 저장소에서 읽으므로 회고를 수정하면 최신 내용, 삭제하면 이후 조회에서 제외(6.8). 튜터는 같은 내부 함수 `_learning_context` 를 재사용(자기 자신을 HTTP 로 부르지 않음) |
| `POST /api/conversations` | 새 대화(제목 "새 대화", 빈 메시지). 선택 `client_request_id` 로 멱등(재요청 200, 같은 대화) — 더블클릭으로 빈 대화가 쌓이지 않게 하려고 추가(DTO 변경) |
| `GET /api/conversations` | 최근 갱신순, 최대 50건, id·title·created_at·updated_at 만 |
| `GET /api/conversations/{id}` | 전체 메시지. assistant 메시지의 `sources`: `[{doc_id, title, source_name, url}]` |
| `POST /api/conversations/{id}/messages` | 요청 `{content(1~1000자), client_request_id}`, 응답 `{user_message, assistant_message, conversation_title, refused}`. 첫 저장은 201, 같은 `client_request_id` 재요청은 중복 저장·AI 재호출 없이 200 |

- **처리 순서:** 소유권 확인(타 UID 403, 없는 id 404) → 멱등 조회 → 메시지 200개 한도(초과 시 409 `CONVERSATION_FULL`) → 요약과 회고(모든 진행 중 학습) → 자료 검색 상위 3개 → **AI 한 번 호출**(`AIClient.generate`, 별도 분류 호출 없음) → 서버 검증 → user·assistant 한 쌍 저장 → 첫 질문이면 제목을 질문 앞 30자로(AI 추가 호출 없음, 공백 정리) → `updated_at` 갱신. 이전 대화는 최근 10개 메시지만 전달.
- **질문 필터:** 구조화 출력 `{relevant, answer, used_source_ids}`. `relevant=false` 이면 AI 가 쓴 답은 버리고 서버의 고정 거절 문구("학습과 관련된 질문에만 답할 수 있어요. … 학습과 관련 있는 질문인데 답하지 못했다면, 어떤 학습이나 주제에 관한 질문인지 덧붙여서 다시 질문해 주세요.")를 저장한다. 거절도 대화에 저장되고 `refused=true`.
- **서버 검증(위반 시 조용히 고치지 않고 재시도, 끝내 실패하면 기존 AI 오류 형식 502/503/504, 아무것도 저장하지 않음):** `relevant=true` 일 때 answer 1~2000자, `used_source_ids` 는 이번에 검색된 문서 id 안에 있어야 함(검색 결과가 없으면 비어 있어야 함). 재시도 때는 위반 사유를 `validation_error` 로 모델에 알려 준다. 출처 제목·URL 은 AI 가 쓰지 않고 서버가 검색 결과에서 만든다.
- **프롬프트(`TUTOR_SYSTEM_PROMPT`):** 질문·이전 대화·회고·요약·자료는 JSON 데이터로 전달하고 그 안의 지시는 따르지 않는다. 자료에 없는 내용을 자료에서 인용한 것처럼 쓰지 않는다. 학습 관련 판정 기준(진행 중 학습, 필요한 개념, 학습 방법·요령)을 명시.
- 데이터 삭제 요청은 대화도 함께 지운다(`USER_OWNED_COLLECTIONS`, 테스트로 확인). 목표 삭제는 대화를 지우지 않는다(테스트로 확인).
- **로그:** 질문, 답변, 회고, AI 원문, 토큰을 남기지 않는다. 테스트(`caplog` DEBUG 수준)와 실서버 로그 검색으로 확인.
- 계약 문서: `backend/schemas.py`, `docs/phase1_design.md` API 표와 ERD, `docs/erd_current.md` 갱신.

## 6. 실제 OpenAI 호출 결과 3건 (원문 없음)

모델 `gpt-4o-mini`(기본값), 위 임시 조각 복사본으로, 브라우저 화면에서 질문:

1. **자료가 있는 학습 질문**(파이썬 리스트 `append`): `relevant=true`, 검색된 조각 `doc_002`(Python 자료구조 공식 가이드), 서버가 만든 출처 1건이 말풍선과 우측 패널에 표시(원문 링크 포함), 답변은 코드 예시 포함. 제목 = 질문 앞 30자.
2. **자료가 없는 학습 일반 질문**(학습 의욕 유지 요령): 검색 결과 없음, `used_source_ids` 비어 있음, 답변 끝에 서버가 "참고한 등록 자료가 없어요" 안내를 붙임, 우측 패널 "참고한 자료가 없어요. 일반적인 학습 조언이에요."
3. **학습과 무관한 질문**(요리): `relevant=false`, 서버의 고정 거절 문구가 저장·표시, 출처 없음.

세 건 모두 재시도 없이 첫 응답이 서버 검증을 통과했다.

## 8. 열린 결정

1. **조각 길이**(§2): 평균 170자. 늘릴지.
2. **검색 동점 처리**: 같은 점수 조각이 많을 때 id 순. 문서 단위 다양화나 가중치 조정이 필요한지(조각이 승인되고 실제 질문이 쌓인 뒤 판단).
3. `ConversationCreateRequest.title` 은 남겨 두었지만 화면은 쓰지 않는다(제목은 첫 질문으로 자동).
4. 메시지 200개 한도(`CONVERSATION_FULL`)는 지시에 없던 안전장치다(Firestore 문서 한 건의 크기 때문). 한도를 바꿀지.
5. 우측 패널의 학습 요약은 대화 시작 때 한 번 읽는다(대화 중 새 기록은 다음 접속 때 반영, 튜터 답변용 요약은 매 질문마다 새로 읽음).
6. `GET /api/data/summary` 의 "진행 중 학습" 범위는 status=active 이다. 일정이 아직 시작되지 않은 학습(시작일이 미래)도 active 이면 포함한다.
