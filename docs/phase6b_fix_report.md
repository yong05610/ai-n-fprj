- **R3** 거부·재시도 횟수 보고(§6). 금지 표현 목록은 바꾸지 않았다.
- 화면, 새 API, 쿨다운·멱등·저장 구조, 프롬프트 어조는 바꾸지 않았다.

## 3. R1 — 서버가 보내는 값 (`user_payload["progress"]`)

`window_record_count`, `window_total_minutes`, `window_total_label`, `this_week_minutes`, `this_week_label`, `weekly_target_minutes`, `weekly_target_label`, `reflection_count`(+ 기존 `completed_tasks`, `total_tasks`). 개별 기록의 `minutes` 는 `records` 에 그대로 있다. 합계는 14일 창 안의 **모든** 기록으로 계산한다(모델에는 최대 40건만 보내도 합계는 전체).

**표기 규칙(한 함수 `insight_rules.format_minutes`, 단위 테스트):** 60분 미만은 "N분"(0분 포함), 정확히 시간 단위면 "N시간", 그 밖은 "N시간 M분". 예: 0→"0분", 59→"59분", 60→"1시간", 61→"1시간 1분", 113→"1시간 53분", 120→"2시간", 420→"7시간".

**프롬프트:** "시간, 분, 건수는 progress 에 제공된 *_label, *_minutes, *_count 값(그리고 records 에 적힌 개별 값)만 그대로 쓴다. 스스로 더하거나 빼거나 평균을 내거나 시간으로 환산하지 않는다. 합계가 필요하면 window_total_label 같은 제공된 표기를 그대로 옮긴다."를 추가했다.

## 4. R1 — 서버 검증의 추출 규칙과 허용 집합 (`backend/insight_rules.py`)

`summary`, `difficulty`, `next_action` 세 필드의 모든 글에서 다음을 정규식으로 뽑는다(아라비아 숫자만).

| 종류 | 정규식 | 분(分)으로 환산 / 값 |
|---|---|---|
| 시간 표현 | `(\d+)\s*시간(?:\s*(\d+)\s*분)?` 와 `(\d+)\s*분` (앞의 것이 먼저라 "1시간 53분"의 "53분"을 따로 다시 읽지 않는다) | "N시간 M분" = N×60+M, "N시간" = N×60, "N분" = N |
| 건수 표현 | `(\d+)\s*(건\|회\|번)(?!째)` | 숫자 그대로("N번째"는 순서라 제외) |

**허용 집합**
- 분: 0, 기간 합계, 이번 주 합계, 주간 목표 분, **개별 기록 각각의 분**. ("2시간"처럼 시간 단위로 쓴 표현도 분으로 환산해 이 집합에 있으면 통과.)
- 건수: 기간 내 기록 수, 사용한 회고 수, 완료 과제 수, 전체 과제 수, **과제별 기록 수**.

허용 집합에 없는 표현이 하나라도 있으면 `AIRetryFeedback` 으로 거부하고, 재시도 payload 의 `validation_error` 에 위반한 표현을 그대로 적어 준다(예: "다음 시간·건수 표현은 제공된 값(*_label, *_minutes, *_count)에 없습니다: 4시간 53분. 제공된 값만 그대로 쓰고 스스로 더하거나 환산하지 마세요."). 재시도가 소진되면 기존대로 502, 저장 없음, 기존 인사이트 유지.

**검증하지 않는 것(문서화):** 날짜·요일·일수("10월 23일", "3일 동안", "목요일", "1주일"), 한글 숫자("세 시간"), 지시서의 표에 없던 "N번" 외 단위("N개" 등). 한글 숫자와 "N개"는 이 규칙의 빈틈이다. "N번"은 모델이 "4번 학습했어요"처럼 자주 쓰는 횟수 표현이라 지시서의 "N건, N회"에 더해 포함했다(§8 열린 결정 1).

**알려진 부작용:** 모델이 스스로 계산한 값은 맞아도 거부된다(예: "하루 평균 28분", "목표까지 5시간 남았어요"). 지시("스스로 더하거나 환산하지 않는다")에 맞는 동작이다.

## 5. R2 — 어려움 규칙

- `_validate_ai_insight`: 입력 회고(`reflection_count` = 모델에 보낸 회고 수, 최대 5)가 2건 미만인데 `difficulty` 가 비어 있지 않으면 거부. `validation_error` 는 지시서 그대로 "회고가 2건 미만이면 difficulty 를 비워야 합니다."
- 회고가 2건 이상이면 채워도 통과(의미 검증은 서버가 할 수 없다). 프롬프트는 "서로 다른 회고 두 건 이상에서 같은 어려움이 확인될 때만, 아니면 빈 문자열, `progress.reflection_count` 가 2 미만이면 반드시 빈 문자열"로 보강했다(어조는 그대로).
- 화면은 `difficulty` 가 비면 그 줄을 숨기는 기존 동작 그대로(변경 없음).

## 6. R3 — 금지 표현 검사의 과잉 여부 (변경하지 않음)

`INSIGHT_FORBIDDEN_TERMS`(연체, 실패, 밀렸, 밀려, 놓쳤, 놓친, 지연, 늦었, 뒤처, 마감)는 그대로다.
- **직전 Phase 6B 의 실제 AI 호출 3회:** 서버 로그상 모두 201 로 끝났고 **502 는 한 번도 없었다.** 다만 그때는 호출 횟수를 세지 않아 재시도(거부) 횟수는 알 수 없다.
- **이번 확인(실제 호출 1회):** 모델 호출 2번(첫 시도가 서버 검증에서 거부되어 한 번 재시도, 그 뒤 통과) → 최종 201. 어떤 규칙에 걸렸는지는 기록하지 않았다(원문을 남기지 않기 위해 호출 횟수만 셌다).
- 정리: 실제 호출 총 4회 중 502 로 끝난 것은 0회, 재시도가 확인된 것은 1회(이번, 새 숫자 검증이 켜진 뒤). 금지 표현 때문에 거부되는 빈도는 이 표본으로는 판단할 수 없다. 사용자 테스트 전에 PM 이 판단할 수 있도록 호출 횟수를 세는 임시 계측 서버(`counting_real_server.py`, 저장소에 넣지 않음)로 더 확인할 수 있다.

## 8. 신규 테스트 요약 (`tests/test_phase6b_fix.py`, 58건)

- 표기 함수: 0, 1, 45, 59, 60, 61, 113, 119, 120, 121, 420, 1500분.
- 추출 규칙: 실제 오류 "4시간 53분" 검출, 제공된 값(1시간 53분, 113분, 7시간, 420분, 32분, 4건, 회고 1건, 4번)은 통과, 다른 값(53분만, 4시간만, 평균 28분, 5건, 3회, 10번 등)은 검출, 날짜·요일·일수·"2번째"·한글 숫자는 검사 안 함, 띄어쓰기 변형, 세 필드 전부 검사.

## 11. 열린 결정

1. **"N번" 포함:** 지시서는 "N시간, N분, N시간 M분, N건, N회"만 말했다. 모델이 횟수를 "N번"으로도 쓰므로 추가했다. 빼도 되는지.
2. **한글 숫자와 "N개":** 검사를 확장할지(오탐이 늘 수 있음).
3. **모델이 스스로 계산한 정확한 값도 거부된다**(평균, 남은 시간 등). 이런 문장이 유용하다면 서버가 `window_average_label` 같은 값을 미리 계산해 주는 방식으로 풀 수 있다.
4. R3(§6): 금지 표현은 현재 거부 빈도를 알 수 없다. 사용자 테스트 전에 더 측정할지.
