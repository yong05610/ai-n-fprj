## 2. R1 (필수) 분야에서 못 맞추면 과정으로 보완 매칭
1. 분야(field) 토큰으로 점수가 0 이면 **과정(course) 토큰만으로 다시 점수를 계산**한다(같은 점수·임계·불용어 규칙, 상위 5건). 분야가 이미 맞는 경우(점수 > 0)는 지금 동작 그대로 둔다.
2. 과정 보완 매칭의 오매칭 방지: 일반어(개발, 기초, 입문, 과정, 코딩 등)만 맞는 경우는 제외하고, **도메인 토큰**(tags 에 있는 웹, react, python 등)이 하나 이상 정확히 일치해야 한다. 1글자 한글 도메인 토큰("웹")은 허용한다.
3. 기존 회귀 테스트: "Java ≠ JavaScript", 일반어만 있는 입력은 빈 결과 등은 유지한다. "UX 디자인 / SQL 기초 → SQL 자료 매칭 없음" 테스트는 이 변경으로 기대가 바뀔 수 있다(과정에 SQL 이 있으면 SQL 자료가 나오는 것이 새 규칙이다). **바뀐 기대값은 목록으로 보고하고, 분야와 과정이 완전히 무관한 사례(예: field "요리", course "한식")는 계속 빈 결과여야 한다.**

## 4. R3 (권고) 짧은 영문 분야
"AI" 같은 2글자 영문 분야는 오매칭 위험 때문에 계속 막혀 있다. 허용 목록(예: `ai`, `ui`, `ux`, `db`, `qa`)을 두고 그 토큰만 정확히 일치할 때 허용한다. 목록 밖의 2글자 영문은 지금처럼 매칭하지 않는다. 구현이 번거로우면 이번에는 보고서에 이유를 적고 넘어가도 된다.
