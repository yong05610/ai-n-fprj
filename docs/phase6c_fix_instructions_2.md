# Phase 6C 수정 지시 2 — 튜터 "함께 보면 좋은 자료"를 출처 유무와 무관하게 (PM, 2026-10-25)

대상: 커밋 6abf810. 끝나면 docs/phase6c_fix_report_2.md 로 보고하고 멈춘다. 5F, 7 은 시작하지 않는다. **이 수정은 PM 지시서(docs/phase6c_dev_prompt.md §1-D)의 설계 결함이다**(개발팀 잘못 아님).

## 1. 문제 (PM 이 실제 AI 호출로 확인)
`related_links`(함께 보면 좋은 자료)는 지시서대로 **출처가 있는 답변에서만** 만들어진다(`tutor.decorate`). 그런데 본문 조각(`rag_chunks.json`)은 10개 문서에만 있어 대부분의 질문에는 출처가 없다. 실제 시험: 학습 = VIBE CODING / 웹 개발의 기초(참고자료 5건 매칭), 질문 "HTML과 CSS는 각각 무슨 역할이에요?" → 출처 없음, `related_links` 빈 목록, 키워드만 3개. 이 학습에 맞는 검토된 링크(MDN HTML·CSS 등)가 있는데 튜터에서는 보이지 않는다.

## 2. R4 (필수)
1. `related_links` 를 **출처 유무와 무관하게** 만든다. 관련 있는 학습 질문(`relevant=true`, 거절 아님)에 대한 모든 답변에 현재 학습(`active_goal_id`)과 매칭되는 검토된 링크를 최대 2건 붙인다(`match_references(field, course)` 재사용, 이미 출처인 자료는 제외하는 기존 규칙 유지).
2. **질문과 겹치는 링크를 앞에 둔다.** 질문 토큰(`rag.topic_tokens`)이 링크의 `tags`·제목과 정확히 일치하면 그 링크를 우선하고, 겹침이 없으면 기존 매칭 순서를 쓴다. 이 순서 결정은 서버가 하며 AI 는 관여하지 않는다(AI 가 링크를 고르거나 쓰지 않는다는 기존 규칙 유지).
3. 화면(튜터 우측 "함께 보면 좋은 자료", 답변 말풍선 하단)은 이미 `related_links` 를 표시하므로 바뀔 것이 거의 없다. 출처가 없을 때 "더 찾아볼 키워드"와 "직접 검색해 보기" 옆에 함께 보이게 되는지 확인하고, 레이아웃이 어색하면 최소한만 조정한다(목업 대조표 갱신은 변경이 있을 때만).
4. 저장하지 않고 응답 때 만드는 기존 방식을 유지한다(`tutor.decorate`).

## 3. 하지 않는 것
다른 매칭 규칙 변경, 링크 자료 추가·삭제, AI 프롬프트·스키마 변경, 프론트 신규 컴포넌트.

## 4. 테스트와 검증 기준
- backend: 출처 없는 답변에도 `related_links` 가 학습과 매칭되는 링크로 채워짐, 질문과 겹치는 링크가 앞에 옴(예: 질문에 "css" 가 있으면 CSS 링크 우선), 겹침이 없으면 기존 순서, 이미 출처로 쓴 자료는 제외, 거절된 질문·매칭 없는 학습은 빈 목록, 최대 2건, 기존 623건 통과.
- 개발팀 실제 AI 확인은 필요 없다(서버가 만드는 값). PM 이 같은 시나리오(VIBE CODING/웹 개발의 기초, 질문 "HTML과 CSS는 각각 무슨 역할이에요?")로 실제 서버에서 `related_links` 에 MDN HTML·CSS 링크가 앞에 오는지 확인한다.
