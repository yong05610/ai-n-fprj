## 0. 역할 분담 (중요)
배포 자체(Render, Vercel 계정, 환경변수 입력, Firebase 도메인)는 **사용자가 콘솔에서 직접** 한다(docs/deploy_guide.md, PM 이 작성). **개발팀은 코드와 저장소 설정만** 고친다. 개발팀은 배포를 하지 않으며 비밀값을 만들거나 쓰지 않는다. 이 Phase 의 목적은 "사용자가 가이드대로 콘솔 설정만 하면 첫 배포가 동작하도록 코드를 준비하는 것"이다.

## 1. 기준
TASK.md Phase 7(7.1~7.8), docs/deploy_guide.md(배포 값과 순서), docs/pre_deploy_checklist.md, CLAUDE.md 핵심 결정. 배포 환경 사실(Render 공식 문서로 PM 이 확인): 신규 서비스의 기본 Python 은 3.14.8(로컬은 3.12.10), 환경변수 `RENDER=true` 자동 설정, 포트 `$PORT`(기본 10000), 시작 명령 `uvicorn main:app --host 0.0.0.0 --port $PORT`, 무료 서버는 15분 무트래픽이면 잠들고 깨우는 데 약 1분.

## 2. 만드는 것 (백엔드)
### B1. 재현 가능한 의존성 (7.4a)
- `backend/requirements.txt` 의 모든 패키지 버전을 **현재 로컬 `.venv`(Python 3.12.10)에서 동작이 확인된 버전으로 고정**한다(`==`). 직접 의존성만 고정하고(fastapi, uvicorn, firebase-admin, openai, python-dotenv, tzdata, pydantic 등 코드가 import 하는 것), 간접 의존성은 pip 가 풀게 둔다. `pytest` 는 배포에 필요 없으므로 `backend/requirements-dev.txt`(`-r requirements.txt` + pytest)로 옮기고 README 의 테스트 명령을 맞춘다. CLAUDE.md 의 실행 안내는 PM 이 고친다.
- **새 빈 가상환경에서 고정한 `requirements.txt` 만으로 설치하고 서버가 뜨는지**(`python -m uvicorn main:app`) 그리고 `requirements-dev.txt` 로 `pytest` 가 전부 통과하는지 확인한다(재현성 증명). 설치에 실패하는 버전이 있으면 이유와 함께 보고한다.
- 저장소 루트에 `.python-version` 파일(내용 `3.12`)을 추가한다(배포 Python 이 기본값 3.14 로 가지 않게 하는 보조 수단. 사용자는 Render 환경변수 `PYTHON_VERSION=3.12.10` 도 설정한다).

### B2. 배포 환경 설정 안전장치 (7.4a, 7.7)
- 이미 있는 규칙: `RENDER` 가 설정되면 `AUTH_MODE=dev`, `STORE_BACKEND=memory` 는 시작을 거부한다(유지). 추가한다.
- **`RENDER` 가 설정된 환경에서 `CORS_ORIGINS` 검사:** 환경변수가 없으면(기본값이 localhost) 시작을 거부한다. 값에 `*`, `localhost`, `127.0.0.1`, `http://`(비 https), 끝의 `/`, 공백 항목이 있으면 거부한다. 거부 메시지는 어떤 규칙에 걸렸는지 알려 주되 값은 출력하지 않는다. 로컬(`RENDER` 없음)에서는 지금 동작 그대로.
- **필수 비밀값 존재 검사:** `RENDER` 가 설정되면 `FIREBASE_SERVICE_ACCOUNT_JSON`, `OPENAI_API_KEY` 가 비어 있을 때 시작을 거부하고 **어떤 이름이 비었는지**만 알린다(값은 출력 금지, 존재만 확인).
- 시작 로그(이미 있음: `startup auth_mode=… store_backend=…`)에 배포에서는 `environment=render` 같은 한 줄을 더하지 않아도 된다. 기존 로그를 유지한다.
- `/docs`, `/redoc`, `/openapi.json`: 환경변수 `API_DOCS_ENABLED`(기본 `true`)로 켜고 끈다. `false` 이면 세 경로가 404. 기본값은 켜짐이다(첫 배포 확인에 필요, TASK 7.4a). 사용자는 테스터를 초대하기 전에 끌지 결정한다.
- `GET /health` 는 그대로 두되(이미 모드를 포함) 배포에서는 `auth_mode=firebase`, `store_backend=firestore` 만 나오게 되어 있는지 확인만 한다.

### B3. Render 첫 요청 지연 대응 (서버 쪽 7.4)
- 서버가 깨어나는 동안(약 1분) 프론트가 보내는 요청이 실패하거나 오래 걸린다. 서버는 별도 처리가 필요 없다. 대신 **가벼운 깨우기 경로**로 `GET /health` 를 이미 쓴다(인증 불필요, 빠름). 확인만 한다.
- 한 가지 확인 보고: 계획 생성(`plan/generate`)의 서버 제한 시간은 60초다. Render 의 요청 시간 제한은 공식 문서에 없어 PM 이 확인하지 못했다. 개발팀도 확인하지 못하면 "미확인"으로 보고한다(배포 후 PM 이 실측).

## 3. 만드는 것 (프론트)
### F1. 콜드스타트 안내와 재시도 (7.4)
- 앱이 열릴 때 **즉시 `/health` 를 먼저 한 번 호출**해 서버를 깨운다(이미 모드 띠를 위해 호출하고 있으면 재사용). 응답이 **8초** 넘게 없으면 화면 상단에 "서버를 준비하고 있습니다. 잠시만 기다려 주세요."를 표시하고, 응답이 오면 사라진다. 최대 **90초**까지 기다리며(2초, 4초, 8초 간격의 재시도), 그래도 응답이 없으면 "서버에 연결하지 못했어요. 다시 시도"와 재시도 버튼을 보인다. 이 대기 중에는 동의 창, 로그인, 다른 API 호출을 시작하지 않는다(깨어난 뒤 시작).
- 튜터 질문, 계획 생성 같은 AI 요청이 네트워크 오류로 실패하면 **입력과 대화 내용을 보존**하고 같은 `client_request_id` 로 재시도할 수 있어야 한다(이미 구현된 규칙을 유지, 변경 없음 확인). 서버가 막 깨어난 직후의 첫 AI 요청이 타임아웃에 걸리는 경우를 위해 AI 요청의 클라이언트 제한 시간(`AI_TIMEOUT_MS`)이 서버 제한(계획 60초, 그 외 설정값)보다 **짧지 않은지** 확인하고, 짧으면 맞춘다.
- 안내 띠는 5C 의 스타일 토큰을 재사용하고 모드 띠와 겹치지 않게 한다. 순수 함수(대기 시간 → 표시 상태 결정)로 분리해 단위 테스트한다(8초 미만, 8~90초, 90초 초과, 응답 도착).

### F2. 배포 설정 누락 방지
- `NEXT_PUBLIC_API_BASE_URL` 이 **프로덕션 빌드에서 비어 있으면** 지금처럼 localhost 로 조용히 요청하지 말고, 화면에 "배포 설정 오류: API 주소가 없어요" 안내를 보이고 요청을 보내지 않는다(개발 모드에서는 기존 기본값 유지). 프로덕션이면서 API 주소가 `http://`(비 https) 이면 같은 안내를 보인다(HTTPS 프론트가 HTTP API 를 호출하면 브라우저가 막으므로 원인 파악용).
- `NEXT_PUBLIC_AUTH_MODE=dev` 로 빌드된 프로덕션 빌드는 모드 띠에 이미 경고가 나온다. 유지 확인만 한다.
- `frontend/.env.example` 에 배포에서 필요한 이름을 주석으로 정리한다(값 없음).

## 4. 통합 점검 (7.1, 7.2, 7.3, 7.5) — 코드가 아니라 확인 보고
TASK 7.1~7.5 는 5B~6C 를 거치며 상당 부분 구현되어 있다. 개발팀은 **구현을 새로 만들지 말고** 아래 표를 채워 보고한다.
1. **화면 대조표(7.1):** 목업(`mockup/index.html`)의 사용자 화면 8개(대시보드, 학습 경로 설정, 학습 과제 계획, 학습 실행 기록, 종합 학습 분석, AI 튜터, 참고자료 보관함, 내 정보·설정)와 관리자 2개(사용자 관리, 사용자 피드백) 각각에 대해 "구현됨 / 구현 안 됨(준비 중 표시) / 의도적으로 다름(이유)" 를 한 줄씩. 코드와 실제 브라우저로 확인하고, 못 본 화면은 "미검증". 관리자 미리보기 메뉴가 MVP 기능과 혼동되지 않는지(비관리자에게는 숨김, 관리자에게도 미구현 4개는 "준비 중") 확인한다.
2. **대시보드 위젯(7.2):** 지표 4개, 오늘 과제 토글, 주간 hit, 인사이트 카드 각각의 로딩·빈 상태·오류·재시도가 있는지(있음/없음/부분)와 없는 곳.
3. **내 정보·설정(7.3):** 지금 있는 것(프로필 조회, 계정 ID 복사, 피드백, 데이터 삭제 요청과 확인 모달)과 TASK 문구 "학습 목표 수정"의 관계. **PM 결정: 학습 목표 수정은 MVP 에서 만들지 않는다**(확정된 계획의 일정이 고정이고 목표를 바꾸면 계획 구조가 어긋난다. 사용자는 새 학습을 만든다). 설정 화면의 안내문에 "학습 목표를 바꾸려면 새 학습 경로를 만드세요"가 없으면 한 줄 추가한다. TASK 7.3 문구는 PM 이 고친다.
4. **소유권·동의·AI 안내·출처·삭제 흐름(7.5):** 화면에 반영되어 있는지 체크리스트(동의 모달, AI 생성 안내 문구 위치, 출처 표시, 데이터 삭제 후 동작). 없거나 어긋난 곳은 목록으로 보고하고 **작은 것은 고치되** 큰 것은 고치지 말고 열린 결정으로 올린다.

## 5. 하지 않는 것
배포 실행, 새 기능, 학습 목표 수정 화면, 디자인 변경, 의존성 업그레이드(고정만), Docker/렌더 설정 파일(`render.yaml`), 모니터링 도구, `.env` 수정.

## 6. 테스트
- backend: `RENDER` 설정 시 CORS 검사(없음, `*`, localhost, http, 끝 `/`, 공백, 정상 https 두 개를 쉼표로), 필수 비밀값 이름 누락 거부(값은 메시지에 없음), `API_DOCS_ENABLED=false` 에서 세 경로 404 와 기본값에서 200, 로컬(`RENDER` 없음)에서 기존 동작 불변, 기존 pytest(현재 772건) 통과. 환경변수는 테스트마다 격리한다.
- frontend: 콜드스타트 상태 순수 함수, 프로덕션 API 주소 검사(없음, http, 정상), 기존 테스트 통과, `npm run typecheck`, `npm test`, `npm run build`. 프로덕션 빌드(`npm run build` 후 `npm run start`)를 로컬 백엔드(빈 포트)에 연결해 콜드스타트 안내가 느린 `/health` 응답(예: 임시 지연)에서 보이고 사라지는지 브라우저로 확인한다. 못 한 것은 "미검증".
- 재현성: B1 의 새 가상환경 설치와 pytest.
- 실제 OpenAI 호출은 이 Phase 에서 필요 없다(0회).
