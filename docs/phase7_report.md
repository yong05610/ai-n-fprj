### 4-2. 대시보드 위젯 (7.2) — 코드 + 브라우저
대시보드는 요청 하나(`/api/dashboard/summary`)로 전체를 불러온다. 그래서 로딩·오류·재시도는 위젯별이 아니라 **화면 전체에 하나**다.
| 위젯 | 로딩 | 빈 상태 | 오류 | 재시도 | 판정 |
|---|---|---|---|---|---|
| 지표 4개 | 있음(화면 전체 "대시보드를 불러오는 중…") | 있음(목표 없음: "아직 학습 목표가 없어요", 최근 학습 미선택 안내) | 있음(화면 전체 오류 + 안내) | 있음("다시 시도") | 있음(화면 단위) |
| 오늘 과제 토글 | 토글 중 비활성(pending) | 있음("이번 주 추천 과제가 없습니다", 모두 완료 안내) | 있음(토글 실패 시 되돌리고 행에 "재시도") | 있음(행별) | 있음 |
| 주간 hit | 화면 전체 | 활동 0이어도 0일 표시(별도 문구 없음) | 화면 전체 | 화면 전체 | 부분(별도 빈 문구 없음) |
| 인사이트 카드(대시보드) | 화면 전체 | 있음(서버가 "부족" 문구 제공: `is_insufficient`/`notice`) | 화면 전체 | 화면 전체 | 있음 |
- 없는 곳: 위젯 하나만 실패해도 화면 전체가 오류 화면이 되는 구조(요청이 하나라서)와 주간 hit 의 빈 문구. 둘 다 큰 변경이라 고치지 않았다.
- AI 인사이트 카드(`종합 학습 분석` 화면의 `InsightCard`)는 자체 로딩·오류·재시도와 같은 요청 번호 재사용 규칙이 있다(코드 확인).

## 미확인·미검증
- **Render 의 요청 시간 제한**(미확인). 계획 생성 서버 한도 60초(최악 180초)가 안에 드는지는 배포 후 실측.
- Render(Linux)에서의 의존성 설치와 시작(이 PC 의 새 가상환경에서만 확인), Render 의 `$PORT`·시작 명령 실행.
- 실제 Firebase 모드 서버의 B2 통과 경로(진짜 Firebase 키 없이 가짜 값으로 시작 검사만 확인, Firebase 연결은 하지 않음).
- 서버가 실제로 약 1분 잠들었다 깨는 상황(브라우저에서 `/health` 를 12초 지연·연결 실패로 흉내 냈다).
- Firebase 프론트 빌드로의 콜드스타트 화면, 모바일 폭, 튜터 실제 답변 화면의 출처.
- `API_DOCS_ENABLED=false` 로 실제 uvicorn 을 띄운 확인은 하지 않았다(`TestClient` 로 404 확인).
- Vercel 빌드 환경(프로덕션 변수가 빌드에 들어가는지) — 배포 후.

## 열린 결정
1. 대시보드를 위젯별 요청으로 나눌지(지금은 요청 하나라 하나만 실패해도 화면 전체가 오류). 큰 변경이라 올린다.
2. 클라이언트 AI 제한 시간(70/200초)과 서버 환경변수 제한이 코드로 연결돼 있지 않다. 서버 제한을 올릴 일이 생기면 함께 올려야 한다.
3. 설정 화면에 보이는 모드 띠와 서버 준비 띠를 배포 후에도 그대로 둘지(Firebase/Firestore 서버면 모드 띠는 자동으로 숨는다).
4. TASK 7.3 문구 정리(학습 목표 수정 제외)와 deploy_guide.md 의 `API_DOCS_ENABLED`, 필수 변수 목록 반영은 PM 담당이다. 이번에 알아야 할 점: 배포에서 `CORS_ORIGINS`, `FIREBASE_SERVICE_ACCOUNT_JSON`, `OPENAI_API_KEY` 중 하나라도 빠지면 서비스가 시작하지 않고 로그에 그 이름이 남는다.
