## 한 줄씩
- **F1 (분야·과정의 `/` 거부, be765db 이후 fix 커밋):** AI 제안 검증(`validate_suggestion`)이 `field`/`course` 의 `/` 를 거부·재시도하고(계속 어기면 AI 제안 없이 pending), 승인 때 수정값(`build_document_fields`)은 422(`details.field` = field 또는 course)로 거부한다. 같은 이유로 관리자 입력 힌트(링크 입력·`/collect` 의 분야·과정)에 `/` 가 있으면 요청 단계에서 422 로 막았다(힌트에 `/` 가 있으면 AI 제안이 영원히 통과할 수 없기 때문 — 요청에 없던 추가이니 불필요하면 알려 주세요). 제목·요약 등 다른 항목은 `/` 허용. 시험 17건(AI 제안 분야·과정 ×4값, 계속 실패, 수정값 3, 다른 항목 허용, 카테고리 분리, 힌트 4). 변이(각 검사 제거) 모두 시험이 실패한다.
- **F2 (`/collect` 가 `direct_link` 를 받지 않음):** 수집기에 `takes_topic` 속성을 두어 `ai_topic` 만 참이고, `/collect` 는 그 외 등록된 수집기를 **422(`details.field`="collector")** 로 거절한다(저장·외부 접근·AI·하루 상한 소모 없음). 없는 수집기 404, 꺼진 `ai_topic` 409 는 그대로. 링크 입력 전용 엔드포인트에서 빈 주소는 기존대로 자동 반려로 기록한다(시험으로 명시). 시험 5건. 가짜 수집기 시험은 `takes_topic = True` 로 갱신.
- **F3 (`test_phase3_auth.py` 고정 날짜, bcd0184, 테스트만·별도 커밋):** 목표일 `2026-12-31` 을 `clock.today() + 120일` 로 바꿨다. 2027-01-04, 2027-06-15, 2028-03-01 로 시계를 바꿔도 이 파일 25건이 모두 통과한다(수정 전에는 12건 실패).
