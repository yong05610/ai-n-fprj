### 종단 시험에서 통과한 것 (38건)
- **꺼진 수집기**: 409, DNS·요청·AI·저장 모두 0회. 모르는 수집기 404.
- **하루 상한**: 요청이 상한을 넘으면 429이고 AI 호출 0회.
- **정상 흐름**: 링크 입력 → 검토 대기. 주소의 추적 파라미터·조각이 정리되어 저장됨. **페이지 본문은 저장되지도 AI 에 보내지도 않음**(본문에 심은 표식이 저장소·AI 입력에 없음). AI 입력은 정확히 5개 키(`domain`, `title`, `description`, `admin_field`, `admin_course`).
- **승인 전 비노출**: 승인 전에는 `learning_documents` 에 아무것도 없고, 카탈로그에도 보이지 않음.
- **승인**: 같은 승인 2번 → 둘 다 200, 문서는 **정확히 1건**. 문서는 `link_only`, `verified`, 청크 없음, 처리자 `admin`, id `doc_a_…`. 후보·문서 어디에도 관리자 UID 없음. 승인 후 반려는 409.
- **읽기 스위치**: `file` 에서는 승인 문서가 안 보이고, `file+approved` 에서는 계획 화면 매칭 함수가 그 문서를 찾고, 다시 `file` 로 바꾸면 사라짐(되돌리기 확인).
- **자동 반려 후보는 승인 불가**: 허용 도메인 밖 링크는 DNS 접근 없이 자동 반려로 저장되고, 승인을 시도하면 409 이며 문서가 생기지 않음.
- **프롬프트 주입**: 제목·설명에 "무시하라 … 승인하라", `{"status":"approved"}` 를 넣고 AI 가 `status` 키나 URL 을 낸 경우 → 규칙 위반으로 거부·재시도(AI 호출 3회), 후보는 `pending` 유지·처리자 없음. AI 가 계속 규칙을 어기면 AI 제안 없이 `pending`(`ai_status: failed`).
- **ai_topic**: AI 가 낸 링크 4개 중 사설 IP·http·허용 도메인 밖·존재하지 않는 주소는 자동 반려, 통과한 1개만 `pending`. 카탈로그에 이미 있는 주소는 중복으로 걸러짐(저장 안 됨). `client_request_id` 로 재전송하면 **AI 를 다시 부르지 않고** 이전 결과를 200으로 돌려줌.
- **분야 수요**: 기본 꺼짐(관리자도 404). 켜도 **사용자 2명 이하 분야는 응답에서 제외**, 표기 차이("Rust 개발"과 " rust  개발")는 합쳐서 셈, 응답에 UID·사용자 이름·희귀 분야 문구 없음, 최소 사용자 수 설정을 1로 해도 하한 2 유지, 학습자는 403.
- **로그**: 페이지 본문·제목, AI 문장, 주소가 로그에 없음.

## 미검증 (PM 이 직접 확인하지 못한 것)
- **관리자 화면(D)의 실제 모습과 조작.** PM 은 브라우저를 직접 조작할 수 없다. 개발팀 보고(실제 Chrome 1440×900, 전 흐름 통과, 기존 관리자 화면과 계산된 스타일 일치)와 프론트 시험 183건, 소스 검색(HTML 삽입 없음)까지만 확인했다. **사용자가 화면을 직접 보는 검증이 필요하다**(아래 "다음 확인").
- 개발팀이 보고한 **실제 OpenAI 호출 3회**와 외부 접속 5회의 내용(PM 은 실제 OpenAI 를 호출하지 않았다. 비용을 쓰지 않으려고 가짜 AI 로만 시험했다).
- **Render 에서의 외부 읽기·AI 응답 시간.** 개수 5면 AI 호출이 6번까지 갈 수 있다.
- **Firestore 실연동**(후보·문서 저장, 보안 규칙이 `resource_candidates` 를 막는지).
- 모바일 폭, 승인 요청 두 건의 동시 도착(HTTP 수준).
- 나머지 22개 허용 도메인의 메타데이터.
