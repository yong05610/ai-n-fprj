# Phase 8C — AI 공급자 확장 (OpenAI + 기관 발급 OpenAI 키 + Gemini 키, 자동 대체)

작성: 검증/PM, 2026-10-26. 상태: **설계 확정(2026-10-26 사용자 답변 반영), 개발 지시 대기.** 이 문서는 `docs/ops_fix_instructions_tutor_key.md`(튜터 전용 키 분리)를 **흡수해 대체**한다. 코드는 아직 바꾸지 않았다.

## 0. 사용자 결정(2026-10-26)
- 지금의 OpenAI 외에 **교육기관이 발급하는 GPT 키와 Gemini 키**로도 인증해 쓸 수 있게 **백엔드 내부에 적용**한다.
- **수정(같은 날, 사용자 답변):** 기관 키는 **일반 OpenAI 키·일반 Gemini 키**다(별도 주소·Azure 아님). 그래서 Azure 전용 구현(주소·배포 이름·API 버전)은 **하지 않는다.** 기관 키로 외부 테스터 서비스를 운영하는 것은 사용자가 **가능하다고 확인**했다(근거 문서는 PM 이 보지 못함, 미검증).
- 기관 키를 **먼저** 쓰고 **응답이 없거나 실패할 때만 정식 키**를 쓴다(순서 설정으로 구현).
- **한쪽이 실패하면 다른 쪽으로 자동 대체**한다.
- 튜터 전용 키 분리(앞 지시서)는 이 구조 안에서 해결한다(§3 "공급자 이름과 기능별 순서").

## 0-1. 2026-10-27 확인된 사실(사용자 제공 화면, 키 값은 기록하지 않음)
- 기관 키 2개는 **코디세이 API 콘솔**(경남테크노파크 전용, `…/gyeongnam/public-api-console`)에서 발급한 `sk-cody-live-…` 키다. **호환 방식: OpenAI 형식 1개, Anthropic 형식 1개.** 진짜 OpenAI·Anthropic 키가 아니라 코디세이 서버를 거치는 키라서 **코디세이의 접속 주소(Base URL)가 있어야** 호출할 수 있다. 콘솔 화면에는 주소가 없고 **미확인(운영자 문의 필요)**.
- 한도: **3,000,000 토큰**, **코디세이 대화(학습 튜터) 화면과 공유되어 차감된다**(사용자 확인). 대화 화면 기준 2026-10-27 사용량 1,253,489 / 3,000,000(42%). 모델별 차감 배수(x0.5, x1, x1.5, x2)가 있어 보인다(추측).
- 대화 화면의 모델: Gemini 3 Flash/3.1 Flash Lite/3.1 Pro, Claude Haiku 4.5/Sonnet 4.6/Opus 4.7/Opus 4.8, GPT-5 Mini/5.4/5.4 mini/5.5. **API 에서 부르는 모델 이름이 같은지는 미확인.**
- 설계 영향: ① 공급자에 **주소 환경변수**가 필요(`OPENAI_API2_BASE_URL`, `CLAUDE_API2_BASE_URL`) ② Claude 는 Anthropic 형식 호출이 필요 ③ **한도가 작고 사용자 본인의 학습 튜터와 공유**되므로 외부 테스터용 "기관 키 먼저" 순서는 권하지 않는다. 권장: **정식 키 먼저, 기관 키는 정식 키 장애 때 예비** 또는 개발·시험 전용. 순서 환경변수로 정하므로 코드는 같다. 최종 결정은 사용자.
- 주소를 받기 전에는 **개발 지시서를 내보내지 않고** 기관 키 시험도 하지 않는다(키를 엉뚱한 서버로 보내지 않기 위해).

## 1. 지금 구조(코드 확인)
- `backend/ai_client.py` 의 `AIClient.generate()` 는 공급자와 무관하다(재시도, 스키마·규칙 검증, 오류 3종). 공급자는 `_raw_complete(system_prompt, user_payload) -> str(JSON 문자열)` 한 함수만 구현하면 된다. 지금 구현은 `OpenAIClient` 하나(`response_format=json_object`, 환경변수 `OPENAI_API_KEY`, `OPENAI_MODEL`, 타임아웃·토큰 상한).
- 모든 AI 호출이 이 한 곳을 지나므로 공급자 추가 때 호출 지점(튜터, 계획, 인사이트, 경로, 참고자료 수집·제안)은 바뀌지 않는다.
- 서버가 AI 결과를 스키마와 규칙으로 검증하므로 **공급자가 바뀌어도 사용자에게 가는 결과의 검증 수준은 같다.** 다만 **출력 품질(한국어, 형식 준수)은 공급자마다 다르다**(§6).

## 2. 설계 원칙
1. **설정하지 않으면 지금과 완전히 같다.** 기본은 OpenAI 하나. 기본값에서 사용자에게 달라지는 것이 없어야 한다.
2. **키와 주소는 환경변수로만**(코드·문서·로그·채팅 금지). 사용자가 Render 와 `backend/.env` 에 직접 입력한다.
3. **대체는 "공급자 장애"에만.** 인증 실패, 한도 초과, 연결 실패, 서버 오류, 시간 초과(그 공급자의 재시도를 끝낸 뒤)일 때만 다음 공급자를 쓴다. **응답이 스키마·규칙 검증을 통과하지 못한 경우는 대체하지 않고** 지금처럼 오류를 낸다(품질 문제를 다른 모델로 덮지 않는다).
4. **조용한 대체 금지:** 어느 공급자를 썼는지 로그에 남긴다(공급자 이름, 기능 이름, 대체 여부, 오류 종류만. 키·주소·내용 없음).
5. 사용자 데이터가 가는 곳이 늘어나므로 **동의 문구가 먼저**다(§5).

## 3. 구성
**공급자 이름**(환경변수로 켠다. 값이 없으면 그 공급자는 없는 것):
| 이름 | 종류 | 환경변수(안) |
|---|---|---|
| `openai` | OpenAI | 기존 `OPENAI_API_KEY`, `OPENAI_MODEL` |
| `openai_tutor` | OpenAI, 튜터 전용 키 | `OPENAI_API_KEY_TUTOR`(선택, 모델은 `OPENAI_MODEL` 공통) — 앞 지시서의 대체 |
| `openai2` | OpenAI, 기관 발급 키(주소는 `openai` 와 같음) | `OPENAI_API2_KEY`, 모델은 `OPENAI_MODEL` 공통(필요하면 `OPENAI_MODEL2`) |
| `gemini` | Google Gemini, 정식(기본) 키 | `GEMINI_API_KEY`, `GEMINI_MODEL` |
| `gemini2` | Google Gemini, 기관 발급 키 | `GEMINI_API2_KEY`(모델은 `GEMINI_MODEL` 공통) |

`azure` 공급자는 만들지 않는다(기관 키가 일반 키로 확인됨). 나중에 필요해지면 새 CR 로 다룬다.

**기능별 순서**(쉼표 목록, 앞에서부터 시도):
- `AI_PROVIDER_ORDER`(기본 `openai`): 모든 기능의 기본 순서. 기관 키 먼저의 예: `openai2,openai,gemini2,gemini`. (설정하지 않으면 `openai` 하나.)
- `AI_PROVIDER_ORDER_TUTOR`(선택): 튜터만의 순서. 예: `openai_tutor,openai2,openai`.
- 순서에 있어도 환경변수가 비어 있으면 건너뛴다. **순서에 없는 공급자는 설정되어 있어도 쓰지 않는다**(키를 넣어 두기만 해서 사용자 데이터가 새는 일 방지). 순서가 비거나 모두 설정되지 않았으면 지금과 같은 "AI 사용 불가" 오류.
- 기능 이름: `tutor`(튜터 답변) / 그 외(경로·계획·인사이트·참고자료 수집·제안)는 기본 순서. 튜터만 별도 순서를 둔다.
- 모델 이름은 공급자별로 다르다(OpenAI `gpt-4o-mini` 등, Gemini 는 모델 ID). 기능별로 다른 모델은 이번에 두지 않는다.

**대체 동작:**
- 한 호출은 순서대로 공급자를 시도하고, 공급자 장애면 다음으로 넘어간다. 마지막까지 실패하면 지금과 같은 오류 응답(`AIUnavailableError` → 지금 형식).
- **시간 예산:** 지금 한 공급자의 최악 시간은 약 `(재시도 3번) × 타임아웃`(계획은 60초×3)이다. 대체가 붙으면 두 배가 되어 Render·프론트 대기 한도를 넘는다. 그래서 **요청당 총 시간 예산**(기본: 현재 최악값 이하, 환경변수로 조정)을 두고, 대체 공급자가 있으면 앞 공급자의 재시도를 줄여(시간 초과는 1회 재시도까지) 총 예산 안에서 다음으로 넘어간다. 값은 개발팀이 제안하고 PM 이 측정으로 확인한다.
- **냉각 시간:** 한도 초과·인증 실패 같은 공급자는 메모리에서 5분 동안 건너뛴다(매 요청마다 실패를 기다리지 않게). 서버가 재시작하면 초기화되어도 된다.
- 쓰기 멱등(`client_request_id`)은 그대로다. AI 호출은 저장 전에 일어나므로 대체 때문에 이중 저장이 생기지 않는다(시험으로 증명).

## 4. 공급자별 구현 메모(공식 문서로 확인한 뒤 구현, 확인 전에는 가정)
- **openai2:** 기존 `OpenAIClient` 에 **키만 다르게 주면 된다**(새 SDK 없음). 기관 키로 쓸 수 있는 **모델 이름이 정식 키와 다를 수 있다**(기관 계정이 허용한 모델만 가능, 미검증) → 실제 호출 확인 때 PM 이 본다. 안 되면 `OPENAI_MODEL2` 로 분리.
- **gemini:** Google 의 공식 SDK 를 쓰고, 시스템 지시문과 JSON 출력 모드(응답 MIME 형식 지정)를 쓴다. SDK 이름과 호출 방식은 **공식 문서로 확인**한다. 키는 일반 API 키로 확인됨(사용자). 기관 키의 모델 허용 범위와 한도는 실제 호출로 확인한다.
- 새 SDK 는 `requirements.txt` 에 **버전을 고정**한다(Phase 7 규칙). 설치가 Render 빌드 시간·메모리에 주는 영향은 측정한다(무료 인스턴스).
- 공급자별 오류를 **기존 3종**(`AIRetryableError`, `AIUnavailableError`, 시간 초과)으로 변환한다. 키·주소·응답 내용을 오류 메시지와 로그에 넣지 않는다.

## 5. 개인정보·약관(코드보다 먼저)
- 학습 기록·회고·질문이 순서에 있는 공급자로 전송된다. **`openai2` 는 받는 회사가 OpenAI 로 같아서 새 수신자가 늘지 않는다.** 새 수신자는 **Google(Gemini)** 뿐이다.
- **사용자 의견(2026-10-26):** 사용자 신원이 노출되지 않으니 별도 조치가 없어도 될 것 같다. **PM 의견:** 신원 정보는 보내지 않지만 학습 목표·회고·질문 **글 자체**가 Google 로 가고, 이름은 없어도 글 안에 개인 정보를 쓸 수 있다. 동의 문구 v1.1 에는 AI 제공자 이름도 해외 처리 안내도 없다. 그래서 **Gemini 를 실제 운영 순서에 넣기 전에 문구 한 줄과 약관 버전 상향(v1.2)**을 권한다. 결정은 사용자(CR-008). **개발은 이 결정과 무관하게 진행**하고, 결정 전에는 `AI_PROVIDER_ORDER` 에 gemini 를 넣지 않는다(기본·개발 환경은 영향 없음).
- **법적 확인(미확인, 사용자·개인정보 담당):** 개인정보 국외 이전 고지와 위탁 여부, 각 공급자의 데이터 보관·학습 사용 조건.
- **기관 키의 사용 조건:** 사용자가 외부 테스터 서비스에 쓰는 것을 **가능하다고 확인**했다. PM 은 그 안내문을 보지 못했다(미검증). 한도·기간이 있을 수 있으므로 **기관 키가 먼저인 순서**에서는 한도 초과가 곧 정식 키로의 대체(비용 발생)임을 알고 있어야 한다. 대체가 일어나면 로그에 남으므로 사용자가 비용을 가늠할 수 있다.
- **기관 키가 먼저일 때의 주의:** 기관 키가 자주 실패하면 매번 지연이 생기므로 냉각 시간(5분)이 중요하다.

## 6. 품질 검증(PM)
- 공급자를 바꾸면 **한국어 출력, JSON 형식 준수, 규칙 준수율**이 달라질 수 있다. 서버 검증이 걸러내지만 거부·재시도가 늘면 시간이 길어진다.
- 공급자마다 **실제 호출 6회 이상**(경로 추천, 계획 생성, 튜터 질문, 인사이트, 참고자료 제안)으로 한국어 출력과 거부율을 PM 이 확인한다(기존 보류 항목 "한국어 출력 수정 재검증"과 함께). 키는 사용자가 넣는다.
- 대체 시험: 첫 공급자 키를 일부러 틀리게 해 두 번째로 넘어가는지, 모두 실패하면 현재와 같은 오류인지, 시간 예산을 지키는지.

## 7. 개발 지시서(승인 후 전달, 한 번에 하나씩)
단계 A~D 중 **A 끝에서 멈추고** PM 이 확인한다. 각 단계는 별도 커밋, push 는 하지 않는다.
- **A. 구조:** 공급자 레지스트리(이름 → 클라이언트 생성), 순서 환경변수 파싱(기본 `openai`), 기능별 순서(`tutor`), 대체 루프, 냉각 시간, 시간 예산, 로그(공급자 이름·기능·대체 여부·오류 종류). 기존 `OpenAIClient` 를 `openai`·`openai_tutor` 로 감싸고 **설정이 없으면 기존 시험이 모두 그대로 통과**해야 한다. `get_ai_client` 의존성 방식(튜터가 다른 순서를 쓰므로 기능별 의존성)과 기존 시험의 가짜 주입이 깨지지 않게 하는 방법은 개발팀이 정하고 보고(기대값은 고치지 않음).
- **B. `openai2`(기관 OpenAI 키):** 기존 클라이언트에 키만 다르게 주는 공급자 추가, 시험(가짜 클라이언트). 새 SDK 없음.
- **C. Gemini(`gemini`, `gemini2`):** SDK 추가(버전 고정), 오류 변환, 시험(가짜 SDK). 공식 문서 확인 내용을 보고서에 적는다.
- **D. 마무리:** `.env.example`, `README.md`/`docs/deploy_guide.md` 환경변수 표(PM 이 작성), 대체 시험, 로그 비밀값 시험.
- 시험(모두 가짜 공급자, 실제 호출 없음): ① 기본값에서 지금과 동일 ② 순서대로 시도하고 장애 시에만 대체, 스키마 실패는 대체하지 않음 ③ 순서에 없는 공급자는 설정돼 있어도 호출되지 않음 ④ 튜터만 별도 순서 ⑤ 냉각 시간, 시간 예산 ⑥ 키·주소·응답 내용이 로그·오류·`/health` 에 없음 ⑦ 모두 실패하면 기존과 같은 오류 ⑧ 대체 중에도 저장은 한 번.
- 비밀값: 개발팀은 키·주소를 만들거나 쓰지 않는다. 실제 호출 확인은 사용자가 키를 넣은 뒤 PM 이 한다.

## 8. 열린 결정·확인 (사용자)
