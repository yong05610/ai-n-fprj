# 서비스기획서 ↔ PRD 대조 조사 (CR-009 ②)

작성: 검증/PM, 2026-10-27. **조사만 했고 서비스기획서.md 와 PRD.md 는 고치지 않았다.** 근거는 두 문서를 처음부터 끝까지 읽은 결과다(줄 번호는 2026-10-27 CR-009 ① 적용 뒤 기준). 코드·목업과의 일치는 이번 조사 범위가 아니다(미검증).

## 1. 역할 기준 (사용자 지적, 2026-10-27)
| 문서 | 담는 것 | 담지 않는 것 |
|---|---|---|
| 서비스기획서 | **무엇을 왜**: 목적, 대상, 핵심 가치, 성공 기준, 범위(포함·제외), 미션 매핑, 일정 큰 틀, 팀·제출물, 향후 방향 | 화면 동작 세부, API 이름, 필드 목록, 처리 절차, 검증 규칙 |
| PRD | **어떻게**: 기능 요구(FR)와 수용 기준, 절차, 데이터 계약, 규칙, 비기능, 위험 | 사업 배경과 큰 목표의 반복 |

## 2. 한눈에 본 결과
- **같은 주제가 두 문서에 겹친 곳: 12곳**(표 A~L). 이 중 **기획서가 PRD 만큼 상세해진(역전) 곳은 6곳**(C, E, F, G, H, I)이고, 나머지 6곳(A, B, D, J, K, L)은 단순 중복이다.
- **서로 내용이 어긋난 곳(낡은 쪽이 있음): 5건**(§4). 평가·제출용 문서라 **내용 맞추기가 역할 재배치보다 먼저**다.
- 기획서에만 있어 **적정한** 부분: 서비스 정의·핵심 가치, MVP 성공 기준(1.2), 미션 필수 기술 매핑 표(4), 팀 역할·제출 체크리스트(9), 향후 방향(10).
- PRD 에만 있어 **적정한** 부분: FR-01~08, API 데이터 계약, 출력 검증, 위험(11).

## 5. 제안 순서 (승인 후 한 건씩)
1. **[완료 2026-10-27, 사용자 승인] 내용 맞추기(위험 낮음)**: §4 의 1~5 를 PRD 기준으로 고친다. 기획서 낡은 문장 수정, PRD 5 의 계획 응답 문장 수정, 데이터 표·번호 정리. 문서 소유자는 PM 이지만 기획서 수정은 사용자 승인 후에만 한다.
2. **역할 재배치(큼)**: §3 의 C, E, F, G, H, I(역전)와 J, K, L(중복)을 기획서는 요약, PRD 는 상세로 옮긴다. 한 번에 하지 않고 **항목 묶음별로 나누어** 하고, 내용이 사라지지 않았는지 줄 단위로 대조한다. 목표 분량: 기획서는 지금보다 눈에 띄게 짧아지고 PRD 는 이동한 내용만큼만 늘어난다.
3. 끝난 뒤 이 문서의 해당 행에 완료 표시를 하고, `docs/change_management.md` CR-009 상태를 갱신한다.

## 6. 주의
- 두 문서는 제출·발표용이다. 용어(WBS→학습 과제, 세션→학습 기록 등)와 그림(`images/PaceMate_서비스구조_설명.png`)이 기획서 1.1 에 있다. 그림은 이번 재배치 대상이 아니다.
- 기획서와 PRD 의 줄이 같은 문장으로 복사된 곳(성능, API 문서화, 개인정보 안내)은 한쪽만 고치면 다시 어긋난다. 재배치하면 이 위험이 사라진다.
