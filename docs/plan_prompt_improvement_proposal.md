# 계획 생성 프롬프트 개선 제안 (사례 비교)

작성: PM, 2026-11-09. 비교 대상: 사용자의 `docs/프롬프트와 응답사례연구.md`(일반 대화형 AI 에 "가톨릭 성경읽기, 3개월, 주 5시간, 가능할까? 늘려야 하나?"를 물은 답)와 PaceMate 의 계획 생성 호출(`docs/ai_prompts_learning_path.md` 순서 3). 관련 내역서: No.4(한 문장 계획, 가능 여부), No.7(조언).

## 1. 사례의 답이 한 일과 PaceMate 가 하는 일

| 단계 | 사례의 AI 답 | PaceMate 현재 | 차이 |
|---|---|---|---|
| ① 필요한 양 추정 | 목표(73권 완독)에 필요한 시간을 먼저 추정: 약 73~95시간 | **하지 않음.** 서버가 가용 시간(주 5시간 × 13주 = 3,900분)을 계산해 "이 값을 넘지 마라"고만 준다 | 가장 큰 차이 |
| ② 가능 여부 판단 | 가용 65시간 < 필요 73~95시간 → "완독이 목적이면 주 7~8시간이 안정적" | 판단하지 않음. AI 는 3,900분 안에 맞추려고 **범위를 조용히 줄인다**(프롬프트: "합계가 클 것 같으면 학습 범위를 줄인다"). 학습자는 범위가 줄었는지 모른다 | "늘려야 하나?"에 답하지 못함 |
| ③ 선택지 제시 | A 완독(주 7~8시간) / B 핵심 읽기(주 5시간) 중 고르게 함 | 없음. 한 번에 계획 하나 | 대화형이라 가능한 부분 |
| ④ 과제의 구체성 | 주차마다 실제 범위(창세기 1–25장)와 주제, 이후 날짜별 장 범위 | 과제마다 제목·설명·예상 분. 범위를 쓰라는 지시가 없어 설명이 추상적일 수 있음 | 프롬프트로 개선 가능 |
| ⑤ 실행 요령 | 하루 50분 = 기도 5·읽기 35·묵상 10, 매일 생각할 질문 3개 | 조언 1건(제목+내용). "단정하지 않고 제안 형태"만 지시 | No.7 과 같은 문제 |
| ⑥ 분야 지식 | 가톨릭 73권, 제2경전, 주교회의 성경 | 분야를 가리지 않는 일반 지시 | 모델 지식에 맡기는 부분 |

## 2. 판단: 프롬프트를 고치는 것이 맞다. 단, 핵심 결정은 지킨다

**고칠 이유:** ①②가 빠져 있어 내역서 No.4 의 "가능할까? 늘려야 하나?"에 답하지 못하고, 학습자 모르게 범위가 줄어든다. 이것은 서비스의 "페이스메이커" 목적과 맞지 않는다.

**지킬 것(핵심 결정):**
- 숫자 계산(가용 시간, 주차 배치, 필요한 주당 시간)은 **서버**가 한다. AI 는 "필요한 양의 추정"만 내고, 이것은 화면에 **"AI 추정"** 으로 표시한다(사례의 73~95시간도 모델의 추정이다).
- AI 결과는 서버가 스키마·규칙으로 검증하고, 어기면 거부·재시도한다.
- 과제 합계가 가용 시간을 넘는 계획은 확정하지 않는다(지금과 같음).

## 3. 개선안 (한 번의 호출 안에서, 호출 수는 늘리지 않음)

### 개선 1. 필요한 양 추정과 범위 표시 (No.4 의 핵심)
출력에 두 항목을 더한다.
```
"full_scope_minutes_estimate": [최소, 최대],   // 목표 수준까지 전체를 하려면 필요한 시간의 추정(분)
"scope_note": "..."                            // 가용 시간 안에 다 못 하면 이번 계획이 어떤 범위를 다루는지 한 문장
```
프롬프트 규칙 추가(초안):
```
- full_scope_minutes_estimate 는 max_total_minutes 와 상관없이, 현재 수준에서 목표 수준까지 전체를 학습하는 데 보통 필요한 시간(분)의 범위 [최소, 최대]이다. 일반적인 학습 속도를 기준으로 추정한다.
- 추정이 max_total_minutes 보다 크면, tasks 는 지금처럼 max_total_minutes 안에서 가장 중요한 범위를 순서대로 다루고, scope_note 에 이번 계획이 다루는 범위와 빠지는 범위를 한 문장으로 쓴다. 범위를 줄였다는 사실을 숨기지 않는다.
- 추정이 max_total_minutes 이하이면 scope_note 는 빈 문자열이다.
```
서버 검증: 최소 ≤ 최대, 10분 이상, 상한(예: 가용 시간의 20배) 이하, 추정 > 가용인데 `scope_note` 가 비면 거부·재시도.
**서버 계산과 화면:** 추정 최소값이 가용 시간보다 크면 서버가 "전체를 하려면 주당 약 N~M시간" 을 계산해 응답에 넣고, 화면 미리보기에 이렇게 보인다.
> AI 추정: 목표 전체에는 약 73~95시간이 필요해요. 지금 계획(주 5시간, 65시간)은 [scope_note]. 전체를 하려면 주당 약 6~8시간이 필요해요. **[주당 시간 바꾸고 다시 만들기]**

사례의 ③(A/B 선택)은 이 버튼으로 대신한다. 학습자가 주당 시간을 늘려 다시 만들면 A, 그대로 확정하면 B 가 된다.

### 개선 2. 과제의 구체적 범위 (사례 ④)
```
- 각 과제의 description 에는 다루는 구체적 범위(예: 책의 장 범위, 단원, 기능 목록)와 그 과제의 핵심 주제를 쓴다. 과제들의 범위는 겹치지 않고 순서대로 이어진다.
```
검증 추가 없음(내용 품질은 사용자 테스트로 확인).

### 개선 3. 실행 요령이 있는 조언 (사례 ⑤, 내역서 No.7)
조언을 한 덩어리에서 세 부분으로 나눈다(출력 항목 변경).
```
"advice_title": "...",
"advice_routine": "...",      // 하루·한 주를 어떻게 쓰면 좋은지(예: 50분 = 준비 5분, 학습 35분, 정리 10분)
"advice_tips": ["...", "..."],// 이 분야에서 도움이 되는 요령 2~4개
"advice_encourage": "..."     // 페이스메이커로서의 한두 문장 격려
```
규칙: 제안 어조, 평가 어조·마감 표현 금지(인사이트와 같은 금지어), 숫자는 user JSON 에 있는 값과 `full_scope_minutes_estimate` 만 사용. 다른 진행 중 학습 연계(No.7)는 user JSON 에 다른 학습의 과정명·주당 시간을 넣는 것으로 함께 처리.

## 4. 하지 않는 것과 이유
- **날짜별(일 단위) 계획:** 사례는 91일 날짜별 장 범위를 만들었지만, PaceMate 는 주 단위 배치이고 내역서 No.6 에서 요일·날짜를 줄이는 방향을 정했다. 일 단위는 과제를 잘게 나누면 되므로 프롬프트의 과제 수 상한(60)을 넘지 않는 선에서 유지.
- **대화로 선택지를 묻는 흐름(A/B):** 한 번의 호출로 끝나는 지금 구조를 유지하고, "주당 시간 바꾸고 다시 만들기" 버튼으로 대신한다. 대화형 계획은 내역서 No.4 2단계(L)에서 검토.
- **특정 출처 링크(주교회의 성경 등):** AI 가 주소를 직접 내지 않는 원칙(IMP-004) 유지. 참고자료는 기존처럼 검토 카탈로그와 검색 링크.

## 5. 영향과 규모
| 항목 | 바뀌는 곳 | 규모 |
|---|---|---|
| 개선 1 | `prompts.py`, `ai_schemas.py`, `main.py`(검증·계산), `schemas.py`·ERD·phase1_design(응답 계약), 미리보기 화면, 시험 | M |
| 개선 2 | `prompts.py` 한 줄 | S |
| 개선 3 | 개선 1 과 같은 곳 + 확정 시 저장하는 조언 구조(`goals` 의 advice), 주간 계획 화면의 조언 표시 | M |

검증: 가짜 AI 시험 외에 **실제 AI 로 여러 분야(성경읽기, Python, 영어 회화 등)를 반복 호출**해 추정 범위의 상식성, scope_note 누락, 금지어를 확인한다. 실제 호출 비용이 든다.

## 6. 제안 순서
개선 2(S) → 개선 1(M) → 개선 3(M, No.7 과 합침). 개선 1 은 사용자 테스트 중이라도 학습자에게 이득이 크지만, 응답 계약이 바뀌므로 테스트 후를 권한다. 개선 2 는 프롬프트 한 줄이라 지금 해도 된다.
