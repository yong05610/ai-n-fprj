# 계획 생성 프롬프트 반복 테스트 결과 (2026-11-09, PM)

목적: `docs/plan_prompt_improvement_proposal.md` 의 개선 2(과제 범위 구체화)와 용어 규칙이 실제로 효과가 있는지, 코드를 바꾸기 전에 확인한다.

## 방법
- 실제 OpenAI 호출(`gpt-4o-mini`, 서비스와 같은 모델·한도·`response_format`). 서비스 코드와 운영 서버는 바꾸지 않았고, 임시 스크립트가 `backend/prompts.py` 의 현재 프롬프트를 읽어 규칙만 덧붙였다.
- 서버와 같은 재시도: 과제 3~60개, 합계 ≤ `max_total_minutes`, 제목 중복 금지를 어기면 이유를 넣어 최대 3번 요청(`main._validate_ai_plan` 과 같은 규칙).
- 비교안: **A** 현재 / **B** + 범위 규칙("각 과제 description 에 장 범위·단원·기능 목록과 핵심 주제, 범위는 겹치지 않고 순서대로") / **C** = B + 공식 용어 규칙("종교·교파, 자격시험, 법령은 입력에 맞는 공식 명칭, 다른 교파·기관 표기를 섞지 않음").
- 분야: 가톨릭 성경읽기(3개월·주 5시간, 가용 3,900분) / Python 기초(8주·주 5시간) / 정보처리기사 필기(3개월·주 8시간). 각 안 5번, 총 45번(재시도 별도).
- "구체적 범위" 판정은 정규식(숫자 범위, "N장·단원", 괄호 안 쉼표 목록)이라 거칠다. 용어는 성경 책 이름·호칭을 직접 셌다.

성경의 실패는 **모두 같은 이유**: 3번 모두 합계가 가용 시간(3,900분)을 넘음(`over` ×3). 실패하면 학습자는 "AI 결과를 해석하지 못했습니다" 오류를 본다.

## 해석
1. **가장 중요한 발견(서비스 문제):** 목표 범위가 가용 시간보다 큰 분야(성경 완독처럼 분량이 정해진 것)에서 계획 생성이 **현재 프롬프트로도 5번 중 1번 실패**하고, 성공한 4번도 모두 재시도를 거쳤다(평균 26초). 사례 연구에서 일반 AI 가 먼저 "필요 73~95시간 > 가용 65시간"을 말한 바로 그 상황이다. 지금 구조는 AI 에게 "넘지 마라"만 주고 범위를 어떻게 줄일지는 맡기는데, 작은 모델이 이를 잘 못 한다.
2. **개선 2(범위 규칙)만 넣으면 오히려 나빠질 수 있다:** 성경에서 실패가 1→3(B), 2(C)로 늘었다. "범위를 겹치지 않고 순서대로"가 전체를 덮으려는 방향으로 작용해 합계가 커진 것으로 보인다. 구체성은 일부 올랐지만(Python 2%→12%, 성경 C 61%) 표본이 작고 들쭉날쭉하다. **개선 2 단독 적용은 권하지 않는다.**
3. **용어 규칙은 효과가 없었다:** C 에서도 성경 용어는 맞는 것 0, 틀린 것 37(출애굽기·애굽·하나님 등). 정보처리기사도 공식 과목명(소프트웨어 설계, 데이터베이스 구축 등)을 거의 쓰지 않고 "컴퓨터 구조, 운영 체제 기초" 같은 일반 주제를 썼다. **프롬프트가 아니라 모델 지식의 한계**로 판단한다.
4. 범위가 가용 시간 안에 들어가는 분야(Python, 정보처리기사)는 세 안 모두 첫 시도에 통과했다.

## 다음 단계 제안
1. **개선 1(필요량 추정 + 범위 명시)을 먼저 시험한다.** AI 가 먼저 전체 필요량을 추정하고, 넘으면 "이번 계획이 다루는 범위"를 정해 그 안에서 과제를 만들게 한다. 같은 스크립트로 성경 실패율이 0 에 가까워지는지, 첫 시도 통과율이 오르는지 본다.
2. **모델 비교를 한 번 한다.** 성경·정보처리기사만, 더 큰 모델로 각 3번. 용어·공식 과목명이 맞으면 "계획 생성만 큰 모델" 선택지가 생긴다(비용 증가를 함께 기록).
3. **운영 확인(사용자):** Render 로그에서 `ai_call_failed kind=schema` 가 테스트 기간에 얼마나 있었는지 보면 실제 테스터가 이 실패를 겪었는지 알 수 있다(로그에는 원문이 없고 실패 종류만 있다).

## 원자료
임시 폴더의 `prompt_abc_out.json`(과제 제목 포함). 저장소에는 올리지 않았다.

## 표본을 직접 읽고 본 것
- **좋아진 것(안정성):** 분량이 큰 성경에서 성공률이 올랐다(가톨릭 3/5 → 5/5, 개신교 3/5 → 4/5), 재시도가 거의 없어졌다. 1단계에서 범위를 먼저 판단한 효과로 보인다. 의견은 하루 30~60분, 주말 요약, 묵상 등 분야에 맞는 내용이 나왔다.
- **나빠진 것(구체성):** 과제가 크고 추상적으로 묶였다(가톨릭 V3 예: "구약 성경 주요 서사와 인물 파악" 등 5개). 장 범위가 사라졌다.
- **해결되지 않은 것(분야 지식):** 가톨릭 1단계 글이 기준 판본을 **"제2천주교 성경"이라고 지어냈고**(실제는 한국천주교주교회의 『성경』), 진행 순서에 출애굽기·사사기·선지서 같은 개신교 명칭을 썼다. 필요량을 "50~100시간"이라 하면서 65시간으로 "가능하다"고 해 앞뒤가 맞지 않았다. 정보처리기사는 필요량을 15~20시간으로 추정했고(현실과 거리 있음) 공식 과목명 대신 "운영체제, 네트워크"를 들었다. `scope_note` 는 범위를 줄이지 않은 Python 에서도 채워지는 등 뜻이 일정하지 않았다.
- 시간: 두 번 호출이라 평균 13~23초(현재 5~22초).

## 판단
- 두 단계 구조는 **"범위가 넘치는 목표에서 실패하는 문제"를 줄이는 효과**가 있다.
- 그러나 사용자가 기대한 **"분야를 아는 사람의 의견"** 은 `gpt-4o-mini` 로는 나오지 않는다. 오히려 그럴듯한 틀린 사실(판본 이름)이 문장으로 나와 더 위험할 수 있다. 사례 연구의 답은 더 큰 모델로 보인다.
- 따라서 다음은 **1단계(자유 의견)만 큰 모델**로 바꿔 보는 시험이다. 2단계 정리는 작은 모델로도 충분하다. API 키로 쓸 수 있는 모델 목록에 `gpt-4.1`, `gpt-5.4-mini`, `gpt-5.4` 등이 있다(2026-11-09 조회).
