# 배포 전 체크리스트 (PM, 2026-10-23)

각 Phase 검증에서 "미검증"으로 남긴 항목을 모았다. Phase 7 배포 직전에 한꺼번에 확인하고, 확인하면 날짜와 확인자를 적는다. 화면 항목은 사용자가 직접 보거나 스크린샷을 보낸다.

## A. Firebase 실연동 (최우선, 한 번도 검증하지 않음)
- [ ] 서버를 `$env:STORE_BACKEND`, `$env:AUTH_MODE` 없이 새 터미널에서 시작(시작 로그의 `auth_mode`, `store_backend` 와 http://localhost:8001/health 로 `firebase`, `firestore` 인지 확인, 화면의 개발 모드 띠가 없어야 함)(docs/firebase_setup_guide.md §8). 새 목표 id 가 20자리 영숫자, 콘솔 Firestore 에 문서 생성
- [ ] 동의 → 계획 확정 → 기록 → 튜터 질문 후 서버를 껐다 켜도 데이터 유지
- [ ] 복수 학습 2개 생성, 3번째 거부(R1), 학습 전환
- [ ] 튜터 대화 저장·목록·새로고침 복원, 메시지 200개 한도(문서 크기)
- [ ] 약관 v1.1 재동의 후 기존 데이터 표시(5E)
- [ ] 피드백 제출·관리자 화면, 데이터 삭제 후 피드백 잔존(콘솔에서 확인)
- [ ] `users`, `goals` 전체 조회(관리자 사용자 목록) 동작
- [ ] 타이머 시작 경합, 피드백 카운터 경합(트랜잭션 필요 여부 판단, post_mvp_backlog.md)

## B. 관리자 (5E)
- [ ] 설정의 "계정 ID 복사" → `backend/.env` 의 `ADMIN_UIDS` → 재시작 → 관리자 그룹 표시(가이드 §9)
- [ ] 일반 사용자(다른 브라우저)에 관리자 메뉴 없음, `#admin-users` 직접 입력 시 대시보드로 복귀

## C. 화면 확인 (사용자 눈으로, 목업과 비교)
- [ ] 5D 주간 계획: 주 이동, 요일 즉시 저장, 연속 변경 시 마지막 값, 저장 실패 재시도, 학습 전환(docs/phase5d_verification.md §4)
- [ ] 6 튜터: 새로고침 복원, 대화 전환, 오류 재시도, 회고 반영, 회고 삭제 후 제외(docs/phase6_verification.md §5)
- [ ] 6B 인사이트: 만들기, 새로고침 유지, 기록 추가 후 오래됨 표시, 부족 안내, 오류 재시도(구현 후)
- [ ] 5C 화면 세부 배치, 모바일·태블릿 폭(대시보드, 실행, 분석, 계획, 튜터, 설정, 관리자)
- [ ] 위저드를 AI 로 처음부터 끝까지 돌린 확정(복원한 초안이 아니라)

## D. 사용자 테스트 1차 지적 재확인 (docs/user_test_round1.md)
- [ ] 1, 3 분야 추천 목록·직무 예시 흐름 / 4 수준 표현 / 7 타이머 전환 후 진행 표시 — 브라우저 재확인
- [ ] 수준 라벨이 직무처럼 보이는 문제 처리 방침 결정(사용자)

## E. 운영·정책 (사용자 결정)
- [ ] 피드백 의견 보관 정책: 테스트 종료 후 요약을 문서로 남기고 콘솔에서 일괄 삭제, 동의 문구에 "테스트 종료 후 삭제" 반영 여부
- [ ] 베타 안내, AI 처리, 개인정보, 삭제 방법 설명(8.1)

## F. 배포(Phase 7) 설정 — 사용자가 직접
(클릭 순서와 값 표: docs/deploy_guide.md, 개발팀 준비: docs/phase7_dev_prompt.md)
- [ ] Render: 시작 명령, 환경변수(OPENAI_API_KEY, FIREBASE_SERVICE_ACCOUNT_JSON, CORS_ORIGINS, ADMIN_UIDS), health 경로. `AUTH_MODE=dev`, `STORE_BACKEND=memory` 는 배포에서 거부됨
- [ ] Vercel: `NEXT_PUBLIC_*` 값(같은 Firebase 프로젝트), `NEXT_PUBLIC_API_BASE_URL` 을 Render URL 로
- [ ] CORS 는 실제 배포 Origin 만 허용(7.7)
- [ ] Firebase 승인된 도메인에 Vercel 도메인 추가
- [ ] Render 첫 요청 지연 안내와 타임아웃(7.4)

## G. 배포 후 핵심 여정 (7.8)
- [ ] 배포 URL 에서 동의 → 계획 → 기록 → 튜터 질문(출처 표시) → 인사이트 → 설정 → 데이터 삭제
- [ ] 비밀값이 로그와 화면, 저장소에 없음(grep -c 로 존재만 확인)
