# 사용자 통합 확인 시나리오 (한 흐름으로 따라가는 순서)

작성: 검증/PM, 2026-10-25. 지금까지 Phase 마다 흩어져 있던 "사용자가 직접 눌러 볼 항목"(docs/phase5d·5e·5f·6·6b·6c_verification.md)과 Firebase 확인(docs/pre_deploy_checklist.md A)을 **한 번에 이어서** 확인하는 순서다. 각 단계마다 **기대 결과**를 적었다. 기대와 다르면 단계 번호와 화면(스크린샷)을 PM 에게 보낸다. 이 문서의 결과는 TASK.md 의 미검증 체크박스(F.4, C6.3, C6.4, 6.7, 6.8, 6.9 등)를 닫는 근거가 된다.

## 0. 준비 (한 번만)
1. 백엔드: **새 PowerShell 창**에서 `cd backend` 후 `.\.venv\Scripts\python.exe -m uvicorn main:app --reload --port 8001 --env-file .env`. 프론트: 새 창에서 `cd frontend` 후 `npm run dev`. (환경변수 `$env:` 줄 없이)
2. 서버 터미널에 `startup auth_mode=firebase store_backend=firestore` 가 보인다. 주소창에 `http://localhost:8001/health` 를 열면 `"auth_mode":"firebase","store_backend":"firestore"`.
3. 화면 위쪽에 "개발 모드예요…" 띠가 **보이지 않는다**.
4. 분야는 **한국어로** 입력한다(영어 입력은 AI 가 영어로 답할 수 있는 알려진 결함, 수정 대기: docs/ops_fix_instructions_korean_output.md).

## 1. 동의와 저장 확인 (Firebase 실연동)
| 단계 | 할 일 | 기대 결과 |
|---|---|---|
| 1-1 | `http://localhost:3000` 열기 | 약관(v1.1) 동의 창. "테스트 피드백을 제출하면 사용자 정보 없이 저장되어…" 문장이 보인다 |
| 1-2 | 체크하고 "동의하고 시작" | 대시보드가 열린다 |
| 1-3 | Firebase 콘솔 → Firestore → `consent_records` | 방금 시각의 새 문서(`terms_version: "v1.1"`) |

## 2. 학습 만들기 (5F 전체 과정 일괄 계획)
| 단계 | 할 일 | 기대 결과 |
|---|---|---|
| 2-1 | 사이드바 "학습 경로 설정" → 분야 입력(예: "웹 개발 입문") → "대표 직무·목표 예시 보기" | 한국어 직무 예시 칩. 칩을 누르면 목표 칸이 채워진다. "예시 다시 보기"는 누를 때마다 다른 예시(정상) |
| 2-2 | "AI 세부 과정·수준 추천" → 과정 하나 선택 → 현재 수준·목표 수준, 주당 시간, 시작일, 목표일 입력 | 목표 수준은 현재 수준보다 뒤인 것만 선택된다 |
| 2-3 | 계획 생성 | 요약에 **"총 예상 시간 … / 가용 시간 …(총 N일, 약 M주)"**, 가용 대비 사용률. 과제가 **주차별로 묶여** 보이고 각 과제에 예상 분과 추천 요일이 있다 |
| 2-4 | 과제 시간을 늘리거나 삭제 | 주차 묶음과 총 시간이 **즉시** 다시 계산된다. 제목을 중복으로 입력하면 오류 |
| 2-5 | 한 과제를 주당 시간보다 길게(예: 주 5시간인데 8시간) 입력 | 허용되고 시작 주에 "이어서 N주에 걸쳐 진행", 이어지는 주에도 표시 |
| 2-6 | 계획 확정(저장) | 완료 안내. 같은 기간에 이미 학습 2개가 있으면 3번째는 "한 날에 진행할 수 있는 학습은 최대 2개" 오류(정상) |
| 2-7 | Firestore 콘솔 → `goals`, `tasks` | 새 문서. `tasks` 문서에 `timeline_start_minutes`, `plan_week_start`, `suggested_weekday` 필드 |

## 3. 서버를 껐다 켜도 데이터가 남는지 (가장 중요)
| 단계 | 할 일 | 기대 결과 |
|---|---|---|
| 3-1 | 백엔드 터미널 `Ctrl+C` 후 같은 명령으로 다시 시작 | 시작 로그에 `store_backend=firestore` |
| 3-2 | 브라우저 새로고침 | 방금 만든 학습과 과제가 **그대로** 보인다 |

## 4. 계획 보기와 요일 바꾸기 (5D)
| 단계 | 할 일 | 기대 결과 |
|---|---|---|
| 4-1 | 사이드바 "학습 과제 계획" | 학습 전환 위젯, 이번 주 과제와 진행 바, 우측 "AI 학습 조언"과 "연결된 참고자료"(자료가 없으면 안내와 "직접 검색해 보기" 링크) |
| 4-2 | "이전 주/다음 주"로 이동 | 첫 주부터 마지막 주까지 이동, "이어서" 과제는 "이번 주 N분 / 총 M분" |
| 4-3 | 과제의 추천 요일 변경 후 새로고침 | 값이 유지된다. 지난 요일을 골라도 연체·경고 표시가 없다 |
| 4-4 | 요일을 빠르게 월→화→토로 바꿈 | 최종 값이 토 |

## 5. 학습 기록, 타이머, 인사이트 (6B)
| 단계 | 할 일 | 기대 결과 |
|---|---|---|
| 5-1 | "학습 실행 기록" → 과제 선택 → 타이머 시작/종료 또는 직접 입력으로 기록 3건 이상, 그중 1건 이상에 회고 입력 | 통계(이번 주 학습 시간, 기록 수)가 갱신된다 |
| 5-2 | 인사이트 카드에서 "인사이트 만들기" | 진행 요약, 다음 행동(회고가 2건 이상이면 반복되는 어려움도). 시간 숫자가 기록 합계와 맞는다. 기록이 부족하면 "기록 N/3, 회고 M/1" 안내 |
| 5-3 | 새로고침 | 저장된 인사이트가 그대로(자동 재생성 없음) |
| 5-4 | 기록을 하나 더 추가 | "기록이 바뀌었어요. 다시 만들 수 있어요" 표시. 60초 안에 다시 누르면 대기 안내 |

## 6. AI 튜터 (6, 6C)
| 단계 | 할 일 | 기대 결과 |
|---|---|---|
| 6-1 | "AI 튜터" → 학습 관련 질문(예: "HTML과 CSS는 각각 무슨 역할이에요?") | 답변 + "AI 생성 · 참고용". 우측에 학습 요약과 최근 회고, "함께 보면 좋은 자료"(MDN 등), 출처가 없으면 "더 찾아볼 키워드"와 "직접 검색해 보기" |
| 6-2 | 등록 자료가 있는 질문(예: "파이썬 리스트 append 쓰는 법") | 답변 아래 출처(제목, 원문 보기) 표시 |
| 6-3 | 학습과 무관한 질문(예: 요리법) | 학습 관련 질문에만 답할 수 있다는 안내 |
| 6-4 | 새로고침, "새 대화", 이전 대화 선택 | 대화와 목록이 복원, 새 대화는 빈 화면, 이전 대화를 열면 이어서 질문 가능 |
| 6-5 | Firestore 콘솔 → `conversations`, `insights` | 새 컬렉션과 문서 |

## 7. 대시보드와 종합 분석
| 단계 | 할 일 | 기대 결과 |
|---|---|---|
| 7-1 | "대시보드" | 이번 주 예정, 오늘 예정 시간, 오늘 추천 과제, 종합 학습 현황(진행 중인 모든 학습), 인사이트 요약 |
| 7-2 | "종합 학습 분석" | 학습별 진행률과 요일별 투입 시간이 실행 화면 수치와 같다 |
| 7-3 | 학습 2개를 만든 뒤 상단 학습 전환 | 전환한 학습의 계획·기록으로 바뀌고 선택이 새로고침 뒤에도 유지 |

## 8. 설정, 피드백, 관리자 (5E)
| 단계 | 할 일 | 기대 결과 |
|---|---|---|
| 8-1 | "내 정보·설정" → 테스트 피드백 작성 후 보내기 | 감사 문구. 점수는 "선택하세요"에서 시작. "사용자 정보가 저장되지 않아 삭제 요청으로 지울 수 없어요" 문장 |
| 8-2 | "계정 ID 복사" → `backend/.env` 의 `ADMIN_UIDS=` 값을 **새 ID(28자 영숫자)**로 교체 → 백엔드 재시작 → 새로고침 | 사이드바에 관리자 그룹(사용자 관리, 사용자 피드백 활성, 나머지 "준비 중") |
| 8-3 | 관리자 "사용자 피드백" | 방금 낸 피드백, 미확인 건수, 평균. 상태 변경이 요약에 반영 |
| 8-4 | 관리자 "사용자 관리" | 마스킹된 ID, 동의, 진행 중 학습 수, 활성 상태만 보이고 과정명·회고는 없다 |
| 8-5 | 다른 브라우저(시크릿 창)로 접속 | 관리자 메뉴가 **없다**(새 계정, 동의 창부터) |

## 9. 결과를 알려 주는 방법
- 단계별로 **통과/실패**만 알려 주면 된다. 실패는 단계 번호, 화면 스크린샷, 서버 터미널의 오류 줄(비밀값 제외).
- PM 은 통과한 단계를 해당 Phase 의 사용자 확인 결과로 기록하고 TASK.md 체크박스를 닫는다. 실패한 것은 수정 지시서로 만든다.
- 모바일 폭과 Render/Vercel 배포 환경 확인은 배포 단계(Phase 7)에서 따로 한다(docs/pre_deploy_checklist.md).
